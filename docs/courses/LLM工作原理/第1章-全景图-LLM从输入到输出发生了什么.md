# 第1章：全景图——LLM 从输入到输出发生了什么

## 回扣本质

我们说 LLM 的本质是"下一个词预测器"。本章要回答的是：当你给 ChatGPT 发一句话，到它吐出回复，这个"预测"具体经过了哪些阶段？建立这个全景图后，后续每一章都是对其中某个环节的深入。

## 正文

### 一、一次对话的生命周期

假设你输入："帮我写一封请假邮件"。从你按下回车到看到回复，发生了以下事情：

```
你的文字 → [Tokenization] → [Embedding] → [Transformer 层 ×N] → [输出概率分布] → 选一个词
                                                                                    ↓
                                                                              把这个词拼回输入
                                                                                    ↓
                                                                              重复，直到生成结束
```

这就是全部。让我们拆开每一步看它**为什么存在**。

### 二、六个阶段，各司其职

**阶段 1：Tokenization（分词）**

- **做了什么**：把你的文字切成一个个"token"——模型能识别的最小单位
- **为什么需要**：计算机不认识汉字和英文，必须先把连续文本打碎成离散的、有限的单元。就像你要用乐高积木搭东西，得先有标准化的积木块
- **类比**：把一篇文章拆成一张张卡片，每张卡片上写着一个词或词的片段

**阶段 2：Embedding（嵌入）**

- **做了什么**：把每个 token（本质是个编号）变成一个高维向量（一组几千个数字）
- **为什么需要**：编号只是标签，不含语义信息。"猫"是编号 3471，"狗"是编号 8832——从编号上看不出它们都是动物。向量可以表达语义关系：相似的词，向量也相近
- **类比**：给每张卡片赋予一个"位置坐标"，让意思相近的卡片自然靠在一起

**阶段 3：Transformer 层（核心计算）**

- **做了什么**：对所有 token 的向量进行反复加工。每一层做两件事：① 让 token 之间互相交流信息（Attention）② 让每个 token 独立"思考"（前馈网络）
- **为什么需要**：初始的 embedding 只知道每个词本身的意思，但不知道上下文。"苹果公司"的"苹果"和"吃苹果"的"苹果"在 embedding 阶段是一样的——需要通过上下文来消歧
- **类比**：一群人坐在圆桌讨论，每一轮大家互相交换信息、各自更新自己的理解。讨论很多轮（很多层）后，每个人对全局都有了更深的理解

**阶段 4：输出概率分布**

- **做了什么**：最后一层的输出向量，经过一个计算变成"词表中每个词的概率"。比如：P("尊敬的")=0.3, P("亲爱的")=0.2, P("你好")=0.15 ...
- **为什么需要**：模型需要从几万个候选词中选出下一个最合适的词。概率分布就是它的"信心表"

**阶段 5：采样（选词）**

- **做了什么**：从概率分布中选一个词。可以选概率最大的（贪心），也可以按概率随机抽（有创造性但可能跑偏）
- **为什么需要**：这就是为什么同样的 prompt，每次回复可能略有不同——采样引入了随机性。Temperature 参数就是控制这个随机性的旋钮

**阶段 6：自回归循环**

- **做了什么**：把刚选出的词拼回输入序列末尾，然后回到阶段 1 重新走一遍全流程，预测下下一个词。循环往复，直到模型输出"结束标记"或达到长度上限
- **为什么需要**：LLM 每次只能预测一个词。它生成一段话不是"一次性想好"，而是"一个词一个词地写"。这意味着——**前面生成的每个词都会影响后面的词**

### 三、一个关键直觉

注意阶段 6 的含义：**LLM 没有"全局规划"能力**。它像一个作家，写到哪算哪，靠前文的铺垫来保持连贯。这解释了很多现象：

- 为什么 LLM 有时前后矛盾——因为它不会"回头改"
- 为什么 prompt 的措辞很重要——不同的前文引导出不同的续写方向
- 为什么 CoT（链式思考）有效——给模型"打草稿"的空间，让它在生成最终答案前先生成推理过程

### 四、训练 vs 推理：两个完全不同的阶段

上面描述的是**推理**（inference）——模型已经学好了，在使用。但这些能力从哪来？

| | 训练（Training） | 推理（Inference） |
|---|---|---|
| **时机** | 事先完成，可能花几个月 | 每次用户提问时实时发生 |
| **目的** | 学习参数（权重矩阵） | 利用已学好的参数做预测 |
| **数据** | 万亿 token 的语料 | 用户的一条 prompt |
| **参数变化** | 不断更新 | 完全冻结不变 |
| **计算量** | 巨大（几千张 GPU 几个月） | 相对小（一张 GPU 几秒） |

**关键认知**：你使用 ChatGPT 时，模型的参数一个都没变。它不会从你的对话中"学习"。所有能力都来自训练阶段。

### 五、与实战项目的关联

回到我们的客服场景：当用户问"我的订单什么时候到"时，LLM 不知道具体订单信息——因为训练数据里没有。这就引出了后面的核心问题：

- 如果知识不在训练数据中 → 需要 RAG（实时检索）
- 如果模型的回复风格/格式不对 → 可能需要 fine-tuning
- 如果只是需要更好的引导 → prompt engineering 可能就够了

> **扩展：为什么叫"大语言模型"？**
> "大"= 参数多（几十亿到几万亿）。"语言"= 训练目标是文本预测。"模型"= 一个数学函数，输入文本输出概率。参数越多，模型能"记住"和"理解"的模式越复杂，但也越贵越慢。

## 思考题

**Q1：为什么 LLM 生成长文本时，越到后面质量越容易下降？**

参考答案：因为自回归机制。每个词的生成都依赖之前所有词，如果中间某个词选得不太好，后面的生成都会受它影响，误差逐步累积。此外，很长的文本可能超出模型在训练时常见的长度分布，导致"不熟悉"的领域表现变差。

**Q2：如果把 Temperature 设为 0（完全贪心，总是选概率最高的词），输出会怎样？**

参考答案：输出会变得完全确定——同样的输入永远得到同样的输出。好处是稳定可控，坏处是可能陷入重复、缺乏创造性。这就是为什么实际应用中通常选一个中间值（如 0.7）：既有一定多样性，又不会太离谱。对于客服场景这种需要准确性的场合，通常 temperature 设得较低。

**Q3：我们说"LLM 使用时参数不变"。那为什么同一个 prompt 多次提问，回复却不同？**

参考答案：因为采样的随机性（阶段 5）。参数不变意味着每次计算出的概率分布是相同的，但从这个分布中"抽签"的结果不同。只有 temperature=0 时，结果才完全一致。这个区分很重要：模型的"知识"是固定的（参数），但"表达"可以多样（采样）。
