# 第6章：对齐——从"续写器"到"助手"

## 回扣本质

预训练给了模型知识和语言能力，但它只会"续写"。本章解决的问题是：**如何把一个"什么都知道但不听话"的续写器，变成一个"能理解指令、有用且安全"的助手？** 这个过程叫**对齐（Alignment）**——让模型的行为与人类意图对齐。

## 正文

### 一、Base Model 的尴尬

直接用 base model 做客服会怎样？

```
用户：我的订单三天了还没到，怎么回事？
Base Model 续写：这是很多消费者都会遇到的问题。在当今电商快速发展的时代...
                （继续写了一篇关于物流的文章）
```

它不是在"回答"，而是在"续写一篇看起来像回答的文本"。它不懂什么是"回答问题"、"帮助用户"、"拒绝不当请求"。

### 二、对齐的三步走

```
Base Model → [SFT] → [RLHF/DPO] → [Safety tuning] → Chat Model
              第一步     第二步          第三步
```

### 三、第一步：SFT（监督微调）

**做了什么**：准备大量"指令-回答"对，让模型学会"被问到 X 时应该回答 Y"的模式。

**本质**：SFT 没有教模型新知识，而是教它一种**新的行为模式**——从"续写"切换到"响应指令"。

**类比**：一个知识渊博的学者从没当过老师。SFT 就是让他旁听一堆教学示范课，学会"学生问问题→老师回答"这个互动模式。

**SFT 的局限**：
- 只能覆盖有限的场景
- 模型学的是表面模式而非深层意图
- 无法表达"这个回答比那个好"的偏好

### 四、第二步：RLHF（基于人类反馈的强化学习）

**核心思想**：不是告诉模型"正确答案是什么"，而是告诉它"A 回答比 B 回答好"。

**流程：**
1. 收集偏好数据：人类标注员对多个回答排序
2. 训练奖励模型：能预测人类会更喜欢哪种回答
3. 用 RL 优化主模型：生成回答→打分→调整参数

**为什么不直接用 SFT？**
因为"好"这个标准很复杂。但人类可以轻松做比较判断，RLHF 把模糊的偏好转化为可优化的信号。

**类比**：SFT 是给厨师食谱照做；RLHF 是让评委试吃排名，厨师根据评委偏好不断调整。

> **扩展：DPO（Direct Preference Optimization）**
> RLHF 流程复杂。DPO 直接用偏好数据优化主模型，跳过奖励模型。效果接近但实现更简单，已被广泛采用。

### 五、第三步：安全对齐

让模型学会拒绝有害请求。方法包括：
- 在 SFT 数据中加入"有害问题→拒绝回答"的样本
- 在 RLHF 奖励信号中加大安全维度权重
- Red teaming：专门找人攻击模型，发现漏洞后修补

### 六、对齐税：好处和代价

| 方面 | 效果 |
|------|------|
| 指令遵循 ↑ | 能理解并执行各种指令 |
| 安全性 ↑ | 拒绝有害请求 |
| 有用性 ↑ | 回答更有帮助、更结构化 |
| 某些能力 ↓ | 过度安全导致拒绝正常问题 |
| 创造性 ↓ | RLHF 倾向于保守回答 |
| 知识 ↓ | 有时为了安全牺牲准确性 |

**这就是"对齐税"**：让模型更安全更有用，代价是损失一部分原始能力。

### 七、与实战项目的关联

回到客服场景：
- 一定要选经过对齐的 Chat/Instruct 版本
- Fine-tuning 在对齐后的模型基础上做，只需要教领域知识和风格
- 注意"过度对齐"问题：system prompt 里明确职责，避免模型过度拒绝

## 思考题

**Q1：为什么"对齐"在 ChatGPT 之前不是热门话题，ChatGPT 之后突然成为核心？**

参考答案：因为之前的模型没有强到被大量普通人使用。当模型足够强大且面向公众时，"模型说什么做什么"就从技术问题变成了社会问题。对齐的重要性与模型的能力和用户规模成正比。

**Q2：RLHF 中的奖励模型本身也是一个模型，它的偏好一定对吗？这会带来什么问题？**

参考答案：不一定对。问题包括：① Reward hacking——模型学会迎合奖励模型的漏洞 ② 标注员偏差——标注团队的文化背景影响"好"的标准 ③ 难以涵盖所有场景。这就是为什么对齐是持续迭代的过程。

**Q3：如果你要为客服场景做 fine-tuning，你会在 base model 上做还是在已对齐的 chat model 上做？为什么？**

参考答案：在已对齐的 chat model 上做。原因：① 不想重新教模型"如何对话" ② 只需注入领域知识和风格 ③ 在 base model 上 fine-tune 可能破坏对齐效果 ④ 数据量更少——几百到几千条样本即可。
