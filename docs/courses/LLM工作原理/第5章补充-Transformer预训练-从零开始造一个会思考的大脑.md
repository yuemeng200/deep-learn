# Transformer 预训练：从零开始造一个会思考的大脑

> 不需要数学背景，只需要逻辑——一步步理解 GPT、Claude 这类模型是如何从一堆随机数字，变成能理解语言的系统。

---

## 导言：预训练是什么，为什么需要它

你现在读这篇文章，用的是几十年积累的阅读能力。你见过无数句子、段落、文章，早就内化了语言的节奏和逻辑。没有人手把手教你每一条语法规则，你是在大量阅读中自然习得的。

大语言模型的**预训练**，做的是同一件事，只不过规模大得离谱：把互联网上几乎所有公开文本塞给一个从零开始的模型，让它在这个过程中自己"悟出"语言的规律。

之所以叫"预训练"，是因为这是后续一切的地基。预训练完成后，得到一个通用的**基础模型**，再经过专门的微调，才能变成会对话的助手、会写代码的工具，或者会分析法律文件的专家。没有预训练，微调就是无米之炊。

> **类比：** 把预训练想象成一个人从出生到大学毕业的整个成长过程——读了大量书籍，接触了大量语言，形成了基本的世界观和思维框架。后续的微调，则是这个人进入某家公司后接受的岗前培训——基础已经在了，只需要针对具体场景再适配。

---

## 第一步：准备语料——喂给模型的"原材料"

**为什么需要这一步？**

模型什么都不知道，它没有先天语感，只有等待被填满的空白权重。要让它理解语言，唯一的办法是让它见过足够多的语言。**语料就是这一切的来源。**

预训练语料来自多个渠道：爬取的网页文本、书籍、学术论文、代码仓库、维基百科……采集之后还需要大量清洗工作：

- **去重：** 同一段内容如果出现数千次，模型会对其死记硬背而非泛化理解
- **过滤低质量内容：** 垃圾网站、乱码、重复广告文本都会拉低模型质量
- **剔除有害内容：** 避免模型过多学习有害语言模式
- **按质量加权：** 高质量内容（书籍、经过审阅的文章）被采样更多次

语料的质量和多样性，在很大程度上决定了模型的上限。一个只见过新闻稿的模型，不会写诗；一个只见过英文的模型，中文会很差。

> **关键认知：** 语料不是越多越好，而是越干净越好。研究表明，用精心筛选的高质量数据训练的小模型，往往胜过用大量劣质数据训练的大模型。"垃圾进，垃圾出"在这里是字面意义上成立的。

## 第二步：分词——把文字变成模型能处理的数字

**为什么需要这一步？**

计算机不认识"天"这个字，只认识数字。我们需要一套系统，把文字**稳定地**映射成整数。这套系统叫**分词器（Tokenizer）**，它将文本切成一段段叫做 token 的片段，再给每个 token 分配一个唯一的 ID。

Token 不等于字或词，它是介于字和词之间、由算法决定的"常用片段"：

- 中文里，常见的词（"今天"、"天气"）通常是一个 token；罕见词可能被拆成更小的片段
- 英文里，"weather" 是一个 token，"unbelievable" 可能被切成 "un + believe + able" 三个 token

分词器本身是在训练主模型**之前**单独训练的，用统计方法（BPE 等算法）找出语料里最高频的片段组合，目标是用尽量少的 token 表示尽量多的文本——压缩率越高，训练和推理效率越好。

```
输入文本：  "今天天气怎么样，适合出门吗？"
切分后的 token：["今天", "天气", "怎么", "样", "，", "适合", "出门", "吗", "？"]
对应的 ID：  [8392,   3701,   5214,   290,   10,   6823,   4491,  88,   17]
```

> **类比：** 分词器相当于字典的索引页——把所有"常用片段"列出来，每个片段编一个号。模型后续的整个学习过程，都是在和这些数字打交道。它看到的世界，是一串串整数序列。

---

## 第三步：设定任务——模型到底在"学"什么

**为什么需要这一步？**

模型要学习，就必须有一个明确的目标——什么叫"做对了"，什么叫"做错了"。没有目标就没有方向，无法优化。

预训练的任务设计极其简单，却意外地强大：

> **给你前面的文字，预测下一个 token 是什么。**

这被称为"下一个词预测"（Next Token Prediction）。这个任务妙就妙在：**不需要任何人工标注**。语料本身就是答案——

把"今天天气怎么样"这句话切开：

| 输入（已知部分） | 正确答案（下一个 token） |
|---|---|
| 今天 | 天气 |
| 今天 天气 | 怎么 |
| 今天 天气 怎么 | 样 |
| 今天 天气 怎么 样 | ，（逗号） |

整个语料库天然地成为数以万亿计的"题目和答案"对，完全自监督。而且，一个 2048 token 的序列，一次前向传播同时产生 2048 个预测——每个位置都在学习，数据利用率极高。

> **关键认知：** 这个"预测下一个词"的任务表面上极简，实际上要做好它，模型**必须**理解语法、事实、逻辑、风格……所有这些，都在隐式地被这一个任务驱动着学习。没有人告诉模型"你要学语法"——它是为了预测准确而自然习得的。

## 第四步：初始化权重——模型从哪里出发

**为什么需要这一步？**

模型的"大脑"是由数百亿个参数（权重）组成的，这些参数最终会携带模型学到的所有知识。但在训练开始之前，它们必须有一个初始值——从何而来？

答案是：**从精心设计过的随机数而来。**

- 不能全部初始化为 0——那样所有神经元行为相同，永远无法分化
- 不能随机得太大或太小——数值不稳定，梯度要么爆炸要么消失
- 通常使用某种正态分布，并根据模型层数和宽度做缩放

这些初始权重什么都不懂——给任何句子，它都输出接近均匀分布的随机概率，预测能力约等于瞎猜。但这正是训练的起点：**一个可以被塑造的空白状态。**

> **类比：** 就像新生儿的大脑——神经元在那里，基本连接结构在那里，但还没有任何记忆、知识或技能。随后的训练，就是这个大脑从白板变为智能系统的成长过程。

---

## 第五步：前向传播——模型给出自己的预测

**为什么需要这一步？**

要改进模型，首先得知道它现在的表现。**前向传播**就是"让模型做一次预测"的过程——把一批 token 序列送进去，经过所有层的计算，输出对下一个 token 的概率分布。

这个过程内部分层进行：

1. **Embedding 层：** 每个 token ID 被换成一个高维向量（比如 4096 个数字），向量里编码了这个词的语义，并加入位置信息（让模型知道这是第几个词）
2. **N 层 Transformer：** 每层有两件事——
   - **自注意力机制：** 所有 token 互相"看一眼"，融合上下文信息。"今天天气怎么样"里，"样"这个 token 能直接看到"今天"、"天气"，并把它们的信息融合进自己的向量
   - **前馈网络：** 每个 token 各自做非线性变换，进一步提炼信息
3. **输出层：** 把最后的向量映射到词表大小的空间，用 Softmax 转换为概率分布

```
输入序列：  "今天天气怎么"
模型输出——词表上各 token 的概率：
  "样"  → 38%
  "好"  → 21%
  "如何" → 14%
  "热"  → 9%
  ...其余词共 18%

语料里的正确答案：  "样"
```

前向传播在训练和推理时走的是**完全相同**的路径。区别在于：训练时走完这一遍之后还要继续做很多事；推理时走完之后直接采样输出就结束了。

---

## 第六步：计算损失——量化"错了多少"

**为什么需要这一步？**

光知道"预测错了"不够——我们需要一个**数字**，精确地描述错了多少。只有这样，后续的调整才有方向和力度。

预训练用的损失函数叫**交叉熵损失（Cross-Entropy Loss）**。它的逻辑很直觉：

- 正确答案是 token X，模型给 X 的概率越高 → 损失越**小**
- 模型给 X 的概率越低 → 损失越**大**，而且是以对数速度放大——概率接近 0 时，损失趋向无穷大

| 场景 | 正确 token 的预测概率 | 损失值 |
|---|---|---|
| 预测很准 | 90% | ≈ 0.1（很小） |
| 预测一般 | 38% | ≈ 1.0 |
| 几乎瞎猜 | 2% | ≈ 3.9（很大） |

训练时，一个 batch 里所有位置的损失会被平均，得到这一步的总损失值。训练初期损失很高（模型在瞎猜）；随着训练推进，损失应该稳定下降。

> **关键认知：** 损失函数是整个预训练的"北极星"——所有的参数更新，最终目的都是让这个数字变小。一次完整的预训练，本质上是在数万亿个 token 上，把平均损失从"瞎猜水平"压到尽可能低的过程。

---

## 第七步：反向传播——把错误变成改进方向

**为什么需要这一步？**

知道损失是多少还不够——我们需要知道，模型里的每一个参数，应该调大还是调小、调多少，才能让损失变小。这就是**反向传播**做的事。

反向传播是微积分中链式法则的工程实现。它从损失值出发，**反向**经过每一层，计算损失对每个参数的偏导数，也叫**梯度**。梯度告诉你：

> 如果把这个参数增大一点点，损失会上升还是下降？上升/下降多少？

这个计算听起来复杂，但得益于自动微分框架（PyTorch、JAX 等），工程师基本不需要手动推导。模型有多少参数，就有多少梯度被同时算出来。对于一个有 700 亿参数的模型，每次反向传播就是同时计算 700 亿个梯度。

反向传播也是训练和推理**最大的区别**所在：推理时根本不做这一步，也不需要保存中间激活值——这就是为什么推理比训练轻得多，同一张 GPU 能跑推理但未必能跑训练。

> **类比：** 想象你在黑暗中摸索走下山坡。你不知道整体地形，但你能感知脚下的坡度——往哪个方向倾斜，倾斜多少。梯度就是这个坡度信息。反向传播的工作，是同时给模型里**每一个**参数都算出"你的坡度是多少"。

---

## 第八步：优化器更新权重——一小步，一小步地变好

**为什么需要这一步？**

有了梯度，还需要决定：更新多大一步？这是**优化器**负责的问题。

最朴素的办法是"梯度下降"：每个参数沿着梯度的反方向（下坡方向）移动一小步，步长由**学习率（Learning Rate）**控制。但实际预训练使用更复杂的优化器，最常见的是 **AdamW**。AdamW 的改进在于：

- **自适应步长：** 历史上变化频繁的参数走小步，历史上变化少的参数走大步，训练更稳定
- **权重衰减：** 防止个别参数变得过大，提升泛化能力

学习率本身也不是固定的，通常按三个阶段调整：

1. **预热（Warmup）：** 训练最初几千步，学习率从极小值逐渐升高——让模型在参数还不稳定时走小步，避免早期的剧烈震荡
2. **稳定训练：** 学习率维持在较高水平，模型快速吸收大量语料的知识，损失稳步下降
3. **退火（Decay）：** 训练末期，学习率逐渐降低至接近 0——模型做精细调整，性能通常在这个阶段有一次明显提升

> **关键认知：** 步骤 5 到步骤 8 组成一个**完整的训练迭代**：前向传播 → 计算损失 → 反向传播 → 优化器更新权重。这个循环在数千张 GPU 上，对数万亿 token，要重复数百万次。每次循环，模型都比上次稍微好一点点。

---

## 第九步：规模与收敛——什么时候算训练完

**为什么需要这一步？**

训练不能无限持续——算力有限，时间有限，而且训练过头也有害（过拟合）。我们需要判断：什么时候停下来是合理的？

判断依据主要是**验证集损失**：从语料中留出一小部分不参与训练，定期在上面评估损失。如果训练集损失在下降而验证集损失不再下降甚至反弹，说明模型开始"死记硬背"而非泛化，该停了。

现代大模型的训练还受**计算预算**约束。研究发现，模型参数量和训练数据量之间存在一个最优比例（Chinchilla 定律）：参数越多，需要的数据量也越多，两者应该同步扩大才能最高效地利用算力。花同样的算力，用小模型配大数据，往往比大模型配小数据效果更好。

训练完成后，模型权重被保存为**检查点（Checkpoint）**文件——数百亿参数的数值，几十到几百 GB 的数据。这就是基础模型的全部，也是送往下一阶段（指令微调和对齐）的"毕业证书"。

## 最终：我们得到了什么

经过以上全部步骤，我们得到一个**基础语言模型（Base Model）**。

**它是什么：**

一组权重矩阵，里面压缩了数万亿 token 的语言规律。它知道"法国的首都是巴黎"，知道"如果 A 大于 B 且 B 大于 C，那么 A 大于 C"，知道莎士比亚的语言风格和技术文档有什么不同。这些知识没有被显式存储，而是分散在数百亿个参数里，以一种我们尚未完全理解的方式编码着。

**它不是什么：**

它只会"续写"，不会"对话"。给它一段话，它会输出最可能的下文——因为这就是它被训练来做的事。它不知道什么是"问题"，不知道什么是"指令"，没有价值观，也不懂礼貌。它就是一台极其强大的**接龙机器**。

**它的意义：**

这是后续一切的基础。在这个基础之上，通过指令微调（SFT），模型学会理解指令格式；通过人类反馈强化学习（RLHF），模型学会什么样的回答是好的。但这些调整都是在预训练奠定的地基上进行的——地基的质量，决定了上层建筑能有多高。

**它的代价：**

从工程角度看，预训练是整个大模型生命周期里耗资最大、最难重复的一步。训练一个顶级模型需要数千张高端 GPU 连续运行数个月，耗资数亿乃至数十亿美元。正因如此，基础模型是整个行业最核心的资产。

而它诞生于一个极其简单的任务：**预测下一个词。**

---

*文章结构回顾：语料准备 → 分词 → 设定任务 → 初始化权重 → 前向传播 → 计算损失 → 反向传播 → 优化器更新 → 收敛判断 → 基础模型*
