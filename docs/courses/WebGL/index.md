# WebGL 渐进式学习课程

## 核心本质

WebGL 解决的根本问题是：**让浏览器直接调用 GPU 的并行计算能力来渲染图形**。

Canvas 2D、Fabric.js、PixiJS，背后都是 CPU 在逐像素"画"图；WebGL 则把这个工作交给 GPU——GPU 有几千个核心，天生为"同时处理大量像素/顶点"而生。

WebGL 的设计哲学是**故意低层**：它不帮你抽象 3D 世界，只暴露 GPU 的渲染管线。这就是为什么 Three.js 存在——Three.js 是 WebGL 上的"便民包装"，而 WebGL 是 Three.js 能存在的原因。理解 WebGL，就是理解所有 3D 库共同依赖的那套底层逻辑。

---

## 课程主线（混合型）

**问题链**：从"GPU 到底在做什么？"出发，逐层追问：数据怎么送进 GPU → GPU 怎么变成像素 → 3D 坐标怎么变成 2D 画面 → 光和材质怎么算 → 最终如何选择合适的工具层。

**验证方式**：每章产出一个可运行的 WebGL 片段，从最简三角形开始，逐章叠加能力，最终整合为一个完整的带光照和纹理的 3D 场景。

---

## 课程大纲

### 第 1 章：从 Canvas 2D 到 WebGL——你已经站在门口了
建立"WebGL 只是另一种 canvas context"的心智模型；理解 CPU 渲染 vs GPU 渲染的本质差异；产出：让 WebGL canvas 清屏为指定颜色（Hello GPU）。

### 第 2 章：渲染管线——GPU 流水线是如何工作的
顶点着色器 + 片元着色器的职责与通信方式；GLSL 语言速览（够用即止）；产出：用原生 WebGL 画出第一个三角形。

### 第 3 章：进入 3D——坐标系、矩阵与相机
五大坐标空间（Local → World → View → Clip → Screen）；MVP 矩阵变换链的直觉理解；产出：让一个 3D 立方体在画面中旋转。

### 第 4 章：光照与材质——让物体"看起来是 3D 的"
经典光照模型（Phong/Blinn-Phong）；法线的作用；漫反射、镜面反射、环境光；产出：为旋转立方体加上方向光，产生明暗感。

### 第 5 章：纹理——给模型穿上外衣
UV 坐标与纹理映射原理；纹理过滤、Mipmap；产出：给立方体贴上一张图片纹理。

### 第 6 章：生态全景——从 WebGL 到 Three.js、Blender、Unity
Three.js / Babylon.js：WebGL 的"便民层"，何时用、各有什么取舍；WebGPU：下一代标准，与 WebGL 的关系；Blender：资产制作工具，与 WebGL 的接口（glTF 格式）；Unity / Unreal：游戏引擎 vs 浏览器 3D 的边界在哪里；场景地图：什么需求该选什么工具。

### 第 7 章：整合与复盘——亲手跑通一个完整的 3D 场景
将前六章所有概念整合：加载 glTF 模型 + 光照 + 纹理 + 相机控制；对比"用原生 WebGL"和"用 Three.js"完成同一任务，感受抽象层的价值；完整知识体系梳理与认知地图。
