# 第 2 章：渲染管线——GPU 流水线是如何工作的

## 回扣本质

上一章我们让 GPU 清了屏——但那还不算"渲染"，只是刷了个背景色。真正的渲染是：把**几何数据**（顶点坐标）变成**像素颜色**输出到屏幕。这个转换过程就是**渲染管线**，是 WebGL 乃至所有 3D 图形的核心本质。

---

## 一、渲染管线是什么

```
你的 JS 数据
    ↓
[顶点着色器]   ← 你写的程序，运行在 GPU，处理每个顶点的位置
    ↓
[光栅化]       ← GPU 自动完成：把三角形"填充"成一堆像素
    ↓
[片元着色器]   ← 你写的程序，运行在 GPU，决定每个像素的颜色
    ↓
屏幕上的像素
```

其中**顶点着色器**和**片元着色器**是你需要编写的两段程序，其余由 GPU 自动完成。

**关键认知**：着色器不是运行在 CPU 上的 JavaScript，而是运行在 GPU 上的一种专用语言——**GLSL**（OpenGL Shading Language）。

---

## 二、着色器的职责分工

**顶点着色器（Vertex Shader）**
- 每个顶点执行一次
- 输入：顶点的原始坐标（和其他属性）
- 输出：该顶点在屏幕上的最终位置（写入内置变量 `gl_Position`）

**片元着色器（Fragment Shader）**
- 三角形内每个像素执行一次
- 输入：插值后的数据（比如颜色、纹理坐标）
- 输出：该像素的颜色（写入内置变量 `gl_FragColor`）

---

## 三、GLSL 速览

```glsl
float  x = 1.0;
vec2   uv = vec2(0.5, 0.5);
vec3   color = vec3(1.0, 0.0, 0.0);
vec4   pos = vec4(0.0, 0.0, 0.0, 1.0);
mat4   transform;
```

**变量修饰符**：
```glsl
attribute vec4 a_position;  // 每个顶点不同的输入（来自缓冲区）
uniform mat4 u_matrix;      // 整次绘制调用共享的值（如变换矩阵）
varying vec4 v_color;       // 顶点 → 片元传递数据（会被自动插值）
```

## 四、画第一个三角形

```html
<!DOCTYPE html>
<html>
<head>
  <style>
    body { margin: 0; background: #111; display: flex; justify-content: center; align-items: center; height: 100vh; }
    canvas { border: 1px solid #333; }
  </style>
</head>
<body>
<canvas id="c" width="600" height="400"></canvas>
<script>
const canvas = document.getElementById('c');
const gl = canvas.getContext('webgl');

// ── 步骤 1：编写着色器源码（GLSL 字符串）─────────────────────────────

// 顶点着色器：每个顶点执行一次，负责确定顶点在屏幕上的位置
// a_position 是从缓冲区传入的顶点坐标，直接赋给 gl_Position 输出
const vertexShaderSrc = `
  attribute vec4 a_position;
  void main() {
    gl_Position = a_position;
  }
`;

// 片元着色器：三角形内每个像素执行一次，负责决定像素颜色
// precision mediump float 声明浮点精度，片元着色器必须显式声明
const fragmentShaderSrc = `
  precision mediump float;
  void main() {
    gl_FragColor = vec4(1.0, 0.5, 0.0, 1.0); // RGBA：橙色，完全不透明
  }
`;

// ── 步骤 2：编译着色器（将 GLSL 字符串编译为 GPU 可执行程序）────────

function createShader(gl, type, source) {
  const shader = gl.createShader(type);    // 创建着色器对象
  gl.shaderSource(shader, source);         // 上传源码
  gl.compileShader(shader);               // 编译
  if (!gl.getShaderParameter(shader, gl.COMPILE_STATUS)) {
    console.error('着色器编译失败:', gl.getShaderInfoLog(shader));
    gl.deleteShader(shader);
    return null;
  }
  return shader;
}

const vertexShader   = createShader(gl, gl.VERTEX_SHADER,   vertexShaderSrc);
const fragmentShader = createShader(gl, gl.FRAGMENT_SHADER, fragmentShaderSrc);

// ── 步骤 3：链接成着色器程序（将顶点 + 片元着色器组合为完整管线）────

const program = gl.createProgram();
gl.attachShader(program, vertexShader);
gl.attachShader(program, fragmentShader);
gl.linkProgram(program);  // 链接：确认两个着色器的 varying 接口匹配

// ── 步骤 4：准备顶点数据，上传到 GPU ──────────────────────────────────

// 三角形的 3 个顶点坐标（NDC 坐标，范围 -1 到 1，原点在画布中心）
// 每行是一个顶点的 (x, y)
const positions = new Float32Array([
   0.0,  0.5,   // 顶部中央
  -0.5, -0.5,   // 左下角
   0.5, -0.5,   // 右下角
]);

const buffer = gl.createBuffer();                          // 在 GPU 上创建缓冲区
gl.bindBuffer(gl.ARRAY_BUFFER, buffer);                   // 绑定为当前操作的缓冲区
gl.bufferData(gl.ARRAY_BUFFER, positions, gl.STATIC_DRAW); // 把数据从 CPU 传到 GPU

// ── 步骤 5：告诉 WebGL 如何从缓冲区读取数据 ───────────────────────────

// 获取着色器中 a_position 变量的位置索引
const positionLocation = gl.getAttribLocation(program, 'a_position');
gl.enableVertexAttribArray(positionLocation); // 启用该 attribute

// 描述缓冲区的数据格式：每个顶点由 2 个 FLOAT 组成，紧密排列（stride=0, offset=0）
gl.vertexAttribPointer(positionLocation, 2, gl.FLOAT, false, 0, 0);

// ── 步骤 6：清屏并执行绘制 ────────────────────────────────────────────

gl.viewport(0, 0, canvas.width, canvas.height); // 设置渲染区域为整个 canvas
gl.clearColor(0.1, 0.1, 0.15, 1.0);            // 设置清屏颜色（深灰蓝）
gl.clear(gl.COLOR_BUFFER_BIT);                  // 执行清屏

gl.useProgram(program);                          // 激活着色器程序
gl.drawArrays(gl.TRIANGLES, 0, 3);             // 从第 0 个顶点开始，取 3 个顶点画三角形
</script>
</body>
</html>
```

## 五、关键概念复盘

**为什么坐标是 0.5、-0.5？**
WebGL 的 NDC 坐标范围是 -1 到 1，中心是 (0,0)。

**`bufferData` 的 `gl.STATIC_DRAW` 是什么？**
给 GPU 的性能提示：数据上传一次、多次使用。还有 `DYNAMIC_DRAW`（频繁修改）和 `STREAM_DRAW`（每帧都变）。

**`vertexAttribPointer` 为什么这么复杂？**
因为缓冲区只是一段原始字节，需要告诉 GPU 如何解读这些字节：每隔多少字节取几个 float。

## 章末思考题

**题 1（理解）**：顶点着色器执行 3 次，片元着色器执行多少次？取决于什么？

> **参考答案**：取决于三角形覆盖的像素数量。一个小三角形可能几十次，铺满屏幕可能几十万次。这是 GPU 并行的核心应用场景。

**题 2（延伸）**：如果想让三角形三个顶点各显示不同颜色（红、绿、蓝），中间自然过渡，应该怎么改？

> **参考答案**：在顶点数据中加入颜色信息，通过 `attribute` 传入顶点着色器，再用 `varying` 传给片元着色器。GPU 光栅化阶段会自动对顶点颜色进行**插值**，中间像素颜色是三个顶点颜色的线性混合。

**题 3（挑战）**：WebGL 只能画三角形吗？`gl.drawArrays` 的第一个参数除了 `gl.TRIANGLES`，还有什么？为什么三角形是 3D 图形的基本单元？

> **参考答案**：还支持 `gl.POINTS`、`gl.LINES`、`gl.LINE_STRIP`、`gl.TRIANGLE_STRIP`、`gl.TRIANGLE_FAN` 等。三角形是基本单元的原因：**任意三点必然共面**，GPU 可以高效光栅化，任意曲面都可以用足够多的三角形来逼近（网格的本质）。
