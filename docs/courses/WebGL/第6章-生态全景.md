# 第 6 章：生态全景——从 WebGL 到 Three.js、Blender、Unity

## 回扣本质

前五章我们一直在手写 WebGL。这一章我们跳出来，看清整个 3D 生态系统：每个工具解决什么问题、站在 WebGL 的哪个层次上，以及最关键的——什么场景选什么工具。

---

## 一、WebGL 生态的层次结构

```
─────────────────────────────────────────────────────
  应用层   │  你的业务代码 / 游戏逻辑 / 可视化逻辑
─────────────────────────────────────────────────────
  引擎层   │  Three.js · Babylon.js · PlayCanvas
           │  （封装场景图、材质、灯光、动画……）
─────────────────────────────────────────────────────
  API 层   │  WebGL 1/2      WebGPU（新一代）
           │  （直接调用 GPU 渲染管线）
─────────────────────────────────────────────────────
  硬件层   │  GPU 驱动  ←  OpenGL / Vulkan / Metal
─────────────────────────────────────────────────────
```

## 二、Three.js——WebGL 的主流封装

同一个旋转纹理立方体，Three.js 版本：

```js
import * as THREE from 'three';

const renderer = new THREE.WebGLRenderer();
document.body.appendChild(renderer.domElement);

const scene  = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(45, window.innerWidth/window.innerHeight, 0.1, 100);
camera.position.set(0, 2, 6);

const geometry = new THREE.BoxGeometry(2, 2, 2);
const material = new THREE.MeshPhongMaterial({
  map: new THREE.TextureLoader().load('checker.png'),
});
const cube = new THREE.Mesh(geometry, material);
scene.add(cube);

const light = new THREE.DirectionalLight(0xffffff, 1);
light.position.set(0.6, 1, 0.8);
scene.add(light);
scene.add(new THREE.AmbientLight(0x333333));

function animate() {
  cube.rotation.y += 0.01;
  renderer.render(scene, camera);
  requestAnimationFrame(animate);
}
animate();
```

**Three.js 抽象掉了什么，没抽象掉什么：**

| Three.js 帮你做了 | Three.js 没做 |
|---|---|
| 场景图（Scene Graph） | 物理模拟（需要 cannon.js 等） |
| 内置材质系统 | 高级后处理（需要 EffectComposer） |
| 几何体库 | 大规模实例化优化 |
| glTF/OBJ 加载器 | 自定义渲染管线（需 ShaderMaterial） |

当你需要自定义着色器效果，Three.js 提供 `ShaderMaterial`——这正是你学原生 WebGL 的价值。

## 三、Babylon.js——另一个选择

| | Three.js | Babylon.js |
|---|---|---|
| 定位 | 通用 3D 库，轻量灵活 | 游戏引擎级别，功能更全 |
| 物理引擎 | 需集成第三方 | 内置（Havok） |
| WebXR 支持 | 基础 | 深度集成 |
| 适合场景 | 可视化、艺术、展示 | 游戏、XR 应用 |

---

## 四、WebGPU——下一代标准

| | WebGL | WebGPU |
|---|---|---|
| 架构 | 全局状态机 | Pipeline 对象，显式状态 |
| 计算着色器 | 不支持 | 支持 |
| 多线程 | 不支持 | 支持 |
| 着色语言 | GLSL | WGSL |

现在：WebGL 仍是生产主力。未来：WebGPU 是方向，Three.js r163+ 已支持 WebGPU 后端。学好 WebGL 概念，迁移成本低。

## 五、Blender——3D 资产的来源

Blender 是开源的专业 3D 创作套件，与 WebGL 的桥梁是 **glTF 格式**：

```js
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';
const loader = new GLTFLoader();
loader.load('model.glb', (gltf) => {
  scene.add(gltf.scene);
});
```

glTF 被称为"3D 界的 JPEG"：开放标准，一个 `.glb` 文件包含网格、材质、纹理、骨骼动画，为 GPU 直接使用优化。

**工作流**：Blender 建模 → 导出 `.glb` → Three.js 加载渲染。

## 六、Unity / Unreal——游戏引擎在哪里

| 选 Three.js/Babylon.js | 选 Unity/Unreal |
|---|---|
| 轻量 Web 展示、可视化 | 复杂游戏逻辑、物理模拟 |
| 需要 SEO / 快速加载 | 团队已有 Unity/C# 积累 |
| 与 Web 深度集成 | 需要主机/移动端同时发布 |

## 七、场景选择地图

```
我需要在浏览器渲染 3D 内容
        │
        ├─ 需要大量自定义渲染效果（着色器级别）
        │       → 原生 WebGL + Three.js ShaderMaterial
        │
        ├─ 标准 3D 展示 / 产品展示 / 数据可视化
        │       → Three.js（首选）
        │
        ├─ 游戏 / 物理 / XR（VR/AR）
        │       ├─ Web 优先 → Babylon.js
        │       └─ 多平台发布 → Unity WebGL 导出
        │
        ├─ 需要大规模 GPU 计算（非渲染）
        │       → WebGPU Compute Shader
        │
        └─ 追求最高性能 / 下一代项目
                → WebGPU + Three.js WebGPU 后端
```

## 章末思考题

**题 1（理解）**：`MeshStandardMaterial` 和 `MeshPhongMaterial` 有什么区别？为什么现代项目更倾向于前者？

> **参考答案**：`MeshPhongMaterial` 基于 Phong 光照模型。`MeshStandardMaterial` 基于 **PBR（基于物理的渲染）**，使用金属度和粗糙度参数，在任何光照环境下表现一致。Phong 需要对每个场景反复调参，PBR 材质一套参数物理上自洽。Blender 导出的 glTF 材质默认也是 PBR 参数。

**题 2（延伸）**：glTF 被称为"3D 界的 JPEG"，这个类比准确在哪里？glTF 和 OBJ、FBX 相比有什么优势？

> **参考答案**：都是广泛支持的开放标准格式。OBJ 只有几何数据，不支持动画；glTF 一个文件包含完整场景（网格+材质+纹理+动画），数据是二进制，加载后几乎不需要处理。FBX 是 Autodesk 私有格式，规范不公开；glTF 是 Khronos 开放标准，各平台实现一致。

**题 3（挑战）**：一家公司想做在线 3D 汽车展示页面（360° 旋转、切换颜色、看内饰）。你会选什么技术栈？设计师建模用什么？

> **参考答案**：**展示页面**：Three.js + GLTFLoader + `MeshStandardMaterial`（PBR 适合汽车漆面）。相机用 `OrbitControls`。颜色切换修改 `material.color`。用 HDR 环境贴图代替实时光源，效果好且性能低。**建模工具**：Blender——专业建模、材质编辑，导出 glTF 给展示页面使用。典型的 Blender → glTF → Three.js 工作流。
