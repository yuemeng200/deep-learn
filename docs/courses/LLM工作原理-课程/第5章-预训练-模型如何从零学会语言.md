# 第5章：预训练——模型如何从零学会语言

## 回扣本质

前四章讲了 LLM 的"身体结构"。本章回答最核心的问题：**这些权重矩阵里的数值是怎么来的？** 答案是：用海量文本反复做"下一个词预测"，让梯度下降自动找到好的参数。这正是我们开篇说的——预测下一个词这个简单目标，如何逼出了语言理解甚至推理能力。

## 正文

### 一、预训练的核心任务：Next Token Prediction

训练目标极其简单：

```
给定："今天天气"
预测下一个词："真" (概率应该高)、"好" (也行)、"轮船" (应该很低)
```

对于训练集中的每句话，模型尝试预测每个位置的下一个词，预测错了就调整参数，让下次更准。

**就这么简单。没有人标注"这句话的情感是正面的"，没有人标注"这里有因果关系"。** 模型为了更好地预测下一个词，被迫自己学会了这一切。

### 二、为什么"预测下一个词"能学出智能？

**要预测 "法国的首都是___"** → 模型必须"记住"世界知识

**要预测 "如果下雨了，我会带___"** → 模型必须理解因果关系

**要预测 "他很高兴，因为他___"** → 模型必须理解情感和动机

**要预测代码的下一个 token** → 模型必须理解程序逻辑

**核心洞察**：语言本身就是对世界知识的压缩表达。能完美预测语言的下一个词，就意味着理解了语言所描述的一切。

这就是"理解即压缩"——模型为了压缩（更好地预测）训练数据，必须提取出数据中的深层规律。

### 三、训练循环：宏观流程

```
重复数万亿次：
  1. 从语料库取一批文本（batch）
  2. 每个位置让模型预测下一个词
  3. 与真实答案对比，算 loss（交叉熵：预测分布与真实分布的差距）
  4. 反向传播：算每个参数对 loss 的贡献
  5. 梯度下降：微调所有参数，让 loss 稍微变小一点
```

**一次参数更新只让模型好那么一丁点。** 但重复几万亿次后，量变引发质变。

### 四、训练数据：吃进去什么，就学出什么

| 数据来源 | 学到什么 |
|---------|---------|
| 网页文本 | 通用语言能力、世界知识 |
| 书籍 | 长文本连贯性、深度推理 |
| 代码仓库 | 编程能力、逻辑思维 |
| 学术论文 | 专业知识、严谨表达 |
| 多语言文本 | 跨语言能力 |
| 对话数据 | 对话能力（有限） |

**关键认知：**
- 训练数据有截止日期。2023年训练完的模型不知道2024年发生的事
- 训练数据有偏差。互联网上英文内容远多于中文，所以模型英文通常更强
- 训练数据有错误。模型也会"学到"错误信息

### 五、Scaling Law：规模的力量

OpenAI 在 2020 年发现了一个惊人的规律：

**模型的能力（loss）与三个因素呈幂律关系：**
- 参数量（N）
- 训练数据量（D）
- 计算量（C）

只要这三者同步增大，模型性能就可预测地持续提升。

**这意味着**：你不需要新的算法突破，只需要更多的 GPU 和数据，就能得到更强的模型。

但 Scaling Law 也告诉你：**三者要平衡**。参数很大但数据不够（欠训练）会浪费参数。LLaMA 的贡献就是证明了：小模型 + 更多数据 > 大模型 + 少数据。

### 六、预训练产出的是什么：Base Model

经过预训练，你得到一个 **Base Model（基座模型）**。

**能做的：**
- 流畅的文本续写
- 拥有海量知识
- 能做各种语言任务——前提是 prompt 写对

**不能做的：**
- 不会"听指令"
- 不知道什么该说什么不该说
- 没有"助手"的人格——它只是个续写器

**类比**：一个读了全世界所有书的人，知识渊博但从没跟人对话过。你跟他说话，他的反应是"继续写下去"而不是"回答你的问题"。

这就是为什么预训练之后还需要**对齐**（第 6 章的内容）。

### 七、与实战项目的关联

回到客服场景：
- **知识截止问题**：模型不知道最新的产品信息、价格变动。→ 这些必须通过 RAG 或 fine-tuning 注入
- **Base model vs Chat model**：API 中你需要经过对齐的 Chat 版本，而非原始 base model
- **模型选择的底层逻辑**：7B 模型的知识量必然少于 70B。如果客服涉及大量专业领域知识，小模型可能存的不够——但可以用 RAG 补

> **扩展：为什么训练一次要花几亿美元？**
> 以 GPT-4 级别为例：几万张 A100/H100 GPU，跑 3-6 个月。按 $2/GPU-hour 算，1万张 GPU × 24h × 120天 ≈ 5700万 GPU-hours ≈ 1亿美元量级。这还不算数据清洗、工程团队的人力。

## 思考题

**Q1：为什么 LLM 有时会"一本正经地胡说八道"（幻觉问题）？从预训练的角度如何理解？**

参考答案：预训练目标是"生成看起来像训练数据的文本"，不是"只说真话"。如果模型在训练中见过很多"X 的首都是 Y"的模式，当被问到它不确定的问题时，它仍然会自信地生成一个符合模式的答案——哪怕是编的。模型没有"不知道"的概念，因为训练数据中没有"我不知道"的标准答案。这是预训练目标（预测≠真实性）的根本局限。

**Q2：为什么 LLaMA（7B）能在很多任务上接近 GPT-3（175B）？二者参数差了 25 倍。**

参考答案：Scaling Law 告诉我们参数量只是三要素之一。LLaMA 用了远多于 GPT-3 的训练数据（1.4万亿 token vs GPT-3 的 3000 亿 token），弥补了参数量的差距。充分训练的小模型 > 欠训练的大模型。

**Q3：如果让你为一家电商公司决定"训练自己的 base model" vs "使用开源 base model + 定制"，你会怎么分析？**

参考答案：几乎总应该选后者。原因：① 训练 base model 需要数亿美元和顶级团队 ② 开源模型的通用能力已经很强 ③ 核心价值在领域数据和应用层 ④ fine-tuning 注入领域知识性价比远高于从零训练。只有极少数场景才值得自训 base model。
