# 课程结业总结

---

## ① 核心理念提炼

### 理念一：意图鸿沟是结构性问题，不是沟通问题

AI Coding 的核心挑战不是"AI 不够聪明"或"你描述得不够好"，而是自然语言的模糊性和 AI 的"合理补全"机制之间必然产生偏差空间。理解了这一点，你就不会再把"AI 给的不是我想要的"归因于运气或工具——它是一个需要用系统性方法（Spec、Harness）来缓解的结构性问题。

### 理念二：Spec 的价值不在于约束 AI，在于强迫人类思考

写 Spec 的过程，本质上是把你脑子里模糊的想法变成可检验陈述的过程。AI 不是最大受益者——**你才是**。一个没写 Spec 就开始 Vibe Coding 的人，和写完 Spec 再开始的人，区别不是"AI 执行得更好"，而是"后者在动手前已经把意图想清楚了"。Spec 是思考的工具，碰巧也能约束 AI。

### 理念三：分层不是为了形式，是为了隔离变更

SDD 的 Constitution/Spec/Plan/Tasks 四层（加上 Implement），核心价值是可追溯性。但更深层的好处是**变更隔离**——需求变了改 Spec，技术选型变了改 Plan，都不需要动其他层。这和软件工程里模块化、分层架构的设计思想完全一致：把不同变化频率的东西放在不同层，让每次变更的影响范围最小。

### 理念四：最好的工程师不站队，而是知道什么时候切换

Vibe Coding、SDD、TDD+AI 各有最强主场。在探索期 Vibe，在定义期 SDD，在实现期 TDD——这不是墙头草，这是工程判断力。面试中展示"我知道每种模式的适用边界"远比展示"我精通某种模式"有价值。

### 理念五：Harness 是框架，不是产品

没有任何一个工具（spec-kit、Cursor、Devin）能完整覆盖 Harness Engineering 的五层。工具解决的是特定层的问题，工程师的角色是**设计并维护这个约束框架**——选什么工具、设什么门槛、定什么流程。这是 AI 时代工程师的核心价值：不是写代码，而是设计让 AI 写好代码的约束体系。

## ② 学员评估与定位

**理解程度**：你对 SDD 的理解在课程过程中呈现出一个明显的特征——**你不会被动接受**。第1章的延伸讨论中，你准确地反驳了"信息损耗"的判断，指出自己的澄清文档已经覆盖了 Spec 层的功能；在第3章之前主动指出缺少工具生态章节；在本章之间的插问（文档是否保留、维护负担、团队不统一怎么办）都体现了批判性思维。这说明你不是在"学习 SDD"，而是在"评估 SDD 对自己实践的增量价值"。

**思维亮点**：
- **同构识别能力**：你很快就能看到自己工作流和 SDD 的结构对应关系，而不是把它当成全新东西
- **务实导向**：你关心的是"这在现实中怎么落地"，不是"这个理论多优雅"
- **折中思维**：团队不全用 SDD 怎么办、hotfix 来不及改文档怎么办——这些都是实践中的真问题

**思维盲区**：
- 在课程前期，对 SDD 和自己工作流的差异倾向于"最小化"（觉得差不多），这有道理，但也可能忽略了一些增量确实有价值（比如 Given/When/Then 的可执行性）
- 对"工具链标准化"的价值可能低估了——你的个人工作流很好，但当它需要变成团队可复用的流程时，标准化工具（如 spec-kit）的价值不只是效率，更是降低协作摩擦

**当前层次**：在这个主题上，你处于**中高级实践者**的位置——有丰富的 AI Coding 实战经验，现在有了完整的理论框架来理解和优化自己的实践，也有了在面试中系统表达的能力。距离"进阶"差的是：在一个真实项目中完整走一遍 spec-kit 流程，获得从工具层面到组织层面的全栈 SDD 实战经验。

## ③ 进阶方向

### 方向一：在一个真实项目中完整实践 spec-kit

能解锁什么：从"理解 SDD"到"用过 SDD"的跨越。面试中说"我理解 SDD 的设计逻辑"和"我在 XX 项目中用 spec-kit 跑了完整流程"是两个完全不同量级的说服力。

### 方向二：Constitution 设计——从工程原则到组织治理

能解锁什么：Constitution 看似简单（"写几条原则"），但设计一份好的 Constitution 需要理解团队的隐性约束、技术债务容忍度、以及哪些原则是不可妥协的。这本质上是从"工程师"到"技术领导者"的视角转换。

### 方向三：多 Agent 协作——Harness 的前沿

能解锁什么：当一个项目中有多个 AI Agent（Claude Code + Cursor + Devin）同时工作时，如何协调它们的输出？如何让它们共享 Spec 和 Plan？如何避免冲突？这是 Harness Engineering Layer 5 的深水区，也是当前行业最前沿的实践之一。

### 方向四：从 SDD 出发，设计自己的 AI Coding 方法论

能解锁什么：你不一定要全盘接受 SDD。基于你的 Vibe Coding 经验和对 SDD 的理解，你可以设计一套自己的方法论——融合两种模式的优势，去掉你不认同的部分。这比"学会 SDD"更高级，它意味着你有了方法论级别的独立思考能力。
