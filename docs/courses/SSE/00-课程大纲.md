# SSE 渐进式课程大纲

## 核心本质

SSE（Server-Sent Events）解决的根本问题是：**如何让服务端主动、持续地向客户端推送数据**。

它的设计哲学是 **"用最简单的方式做对的事"**。SSE 基于普通 HTTP 协议，采用单向推送模型，自带重连机制，文本协议可读可调试。它刻意舍弃了 WebSocket 的全双工能力，换来的是：
- 极低的实现复杂度（服务端几行代码，浏览器原生 API）
- 天然兼容 HTTP 基础设施（代理、负载均衡、CDN、防火墙）
- 自动重连 + 事件 ID 追踪，断线不丢消息
- 纯文本协议，调试透明

一句话总结：**SSE 是"够用就好"的哲学典范——当你只需要服务端往客户端推数据时，它就是最正确的选择。**

## 实战项目

**实时通知 Dashboard** — 一个包含通知推送、实时数据监控、任务进度追踪的仪表盘应用。

为什么选它：
- 覆盖 SSE 三大典型场景：消息推送、数据流式更新、进度追踪
- 自然引出连接管理、错误处理、重连、多客户端等生产级问题
- 可以随课程进展逐步扩展，从最简单的 demo 成长为完整应用

## 课程大纲

### 第1章：SSE 的本质 — 为什么不是 WebSocket？
建立 SSE 的心智模型。对比长轮询、WebSocket、SSE 三种实时通信方案的优劣与适用场景。解析 SSE 协议格式（event/data/id/retry）。动手写一个最小 SSE demo——Node.js 服务端推送时间，浏览器实时显示。

### 第2章：从零搭建 SSE 服务端
用 Node.js 搭建完整的 SSE 服务端。掌握事件格式规范、多事件类型、自定义事件 ID。实现连接管理：客户端注册、断开检测、资源清理。产出：一个支持多客户端连接的 SSE 服务端。

### 第3章：前端消费 SSE 流
深入 EventSource API：open/message/error 事件、readyState 状态管理。学会在前端优雅地消费 SSE 事件并更新 UI。探讨与 React/Vue 状态管理的集成模式。产出：前端 Dashboard 框架，实时消费并展示 SSE 事件。

### 第4章：原生 EventSource vs fetch SSE — 前端双方案对比（重点章）
原生 EventSource 只支持 GET 请求、无法自定义请求头和请求体，这在实际业务中是严重限制（如 AI 对话需 POST body 传历史、需 Authorization 头做认证）。本章全面对比两种前端 SSE 消费方案：原生 EventSource 与 fetch + ReadableStream 手动解析。深入分析各自的能力边界、适用场景、重连机制差异，并动手实现一个通用的 fetch-based SSE 客户端。产出：双方案对比决策表 + 可复用的 fetch SSE 工具函数。

### 第5章：生产级 SSE — 错误处理、重连与心跳
掌握让 SSE 在生产环境稳定运行的关键技术：自动重连机制与 Last-Event-ID 的妙用、心跳保活防止连接被中间层掐断、服务端优雅关闭。产出：生产可用的 SSE 连接管理层（含重连策略 + 心跳机制）。

### 第6章：SSE 的坑与填坑指南（重点章）
系统梳理 SSE 开发中最常踩的坑：Nginx/CDN 代理缓冲导致事件不实时、浏览器 6 连接限制、内存泄漏、跨域问题。每个坑都有对应的解决方案和代码演示。产出：避坑检查清单 + 完整踩坑演示代码。

### 第7章：SSE 面试深度追问 — 从原理到实战
基于真实项目（wizstar-fe-2）的 SSE 踩坑点，设计 8 条追问链，每条从基础问题开始逐步深入。覆盖：选型决策、连接管理与重连、消息去重与状态管理、生产部署、服务端架构、安全认证、性能优化、系统设计。前后端均有涉及。
