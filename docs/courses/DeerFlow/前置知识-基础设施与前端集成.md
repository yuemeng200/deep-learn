## 1. FastAPI — API 网关框架

**其他语言类比**：FastAPI ≈ Spring Boot（Java）或 Express + TypeScript 类型推导。核心思想：用 Python 类型注解自动生成 OpenAPI 文档和参数验证。

### 1.2 依赖注入 `Depends()`

FastAPI 的 `Depends()` 类似 Spring 的 `@Autowired`——声明"我需要这个依赖"，框架自动注入。

`backend/app/gateway/deps.py:33`：
```python
def get_config(request: Request) -> AppConfig:
    """从 app.state 取出配置——所有路由共用"""
    config = getattr(request.app.state, "config", None)
    if config is None:
        raise HTTPException(status_code=503, detail="Configuration not available")
    return config
```

路由中使用：
```python
# FastAPI 自动调用 get_config()，把结果传给 config 参数
async def list_models(config: AppConfig = Depends(get_config)) -> ModelsListResponse:
    ...
```

项目中的常见依赖：
| `Depends(...)` | 注入什么 | 用途 |
|---------------|---------|------|
| `Depends(get_config)` | `AppConfig` | 应用配置 |
| `Depends(get_run_manager)` | `RunManager` | Agent 运行管理 |
| `Depends(get_stream_bridge)` | `StreamBridge` | SSE 流式推送 |
| `Depends(get_checkpointer)` | Checkpointer | 状态持久化 |

```python
    async with langgraph_runtime(app):         # 2. 初始化 LangGraph 运行时
```

## 2. SSE（Server-Sent Events）与流式架构

**核心洞察**：DeerFlow 的"实时打字效果"依赖 SSE——一种 HTTP 长连接协议，服务端持续推送事件给浏览器。

### 2.1 SSE 原理

```
浏览器                              后端
  │                                   │
  │── GET /stream ──────────────────→│  普通 HTTP 请求
  │                                   │
  │←── data: {"type":"text","delta":"你"} ──│  服务端持续推送
  │←── data: {"type":"text","delta":"好"} ──│
  │←── data: {"type":"tool","name":"bash"} ─│
  │←── data: [DONE] ────────────────│  结束信号
```

与 WebSocket 的区别：SSE 是**单向**（服务端→客户端）、**纯 HTTP**、自动重连。适合 Agent 流式输出场景。

### 2.2 FastAPI 的 SSE 端点

`backend/app/gateway/routers/thread_runs.py:126`：
```python
from fastapi.responses import StreamingResponse

@router.post("/{thread_id}/runs/stream")
async def stream_run(...) -> StreamingResponse:
    record = await start_run(body, thread_id, request)

    return StreamingResponse(
        sse_consumer(bridge, record, request, run_mgr),  # async generator
        media_type="text/event-stream",                   # SSE MIME 类型
        headers={
            "Cache-Control": "no-cache",      # 不缓存
            "Connection": "keep-alive",       # 长连接
            "X-Accel-Buffering": "no",        # 告诉 nginx 不要缓冲
        },
    )
```

`sse_consumer` 是一个 async generator，从 `StreamBridge` 消费事件并格式化为 SSE 格式。

### 2.3 StreamBridge — 生产者/消费者解耦

Agent 运行在后台线程中，SSE 端点在 async handler 中。两者通过 `StreamBridge` 解耦：

`backend/packages/harness/deerflow/runtime/stream_bridge/base.py:37`：
```python
class StreamBridge(abc.ABC):
    # Agent worker（生产者）调用
    async def publish(self, run_id: str, event: str, data: Any) -> None: ...

    # SSE endpoint（消费者）调用
    def subscribe(self, run_id: str) -> AsyncIterator[StreamEvent]: ...
```

完整流程：
```
Agent.astream() → worker 调用 bridge.publish() → 内存队列 → sse_consumer() → SSE → nginx → 浏览器
```

### 2.4 Nginx 的 SSE 代理配置

`docker/nginx/nginx.conf`：
```nginx
location /api/langgraph/ {
    proxy_pass http://gateway:8001;
    proxy_http_version 1.1;

    # 关闭缓冲——让 SSE 事件立即到达浏览器
    proxy_buffering off;
    proxy_cache off;
    proxy_set_header X-Accel-Buffering no;
}
```

如果 Nginx 开启缓冲，SSE 事件会被攒在一起批量发送，用户看不到"打字效果"。

## 3. SQLAlchemy async — 数据持久化

**其他语言类比**：SQLAlchemy ≈ Java Hibernate / .NET Entity Framework，但 Python 版用声明式类型注解定义模型。

### 3.1 模型定义（SQLAlchemy 2.0 风格）

项目使用 SQLAlchemy 2.0 的 `Mapped` + `mapped_column` 语法：

`backend/packages/harness/deerflow/persistence/models/run_event.py`：
```python
from sqlalchemy.orm import Mapped, mapped_column
from deerflow.persistence.base import Base

class RunEventRow(Base):
    __tablename__ = "run_events"

    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)
    thread_id: Mapped[str] = mapped_column(String(64), nullable=False)
    run_id: Mapped[str] = mapped_column(String(64), nullable=False)
    user_id: Mapped[str | None] = mapped_column(String(64), nullable=True, index=True)
    event_type: Mapped[str] = mapped_column(String(32), nullable=False)
    content: Mapped[str] = mapped_column(Text, default="")
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True))
```

关键区别 vs 旧式 SQLAlchemy：
```python
# 旧式（SQLAlchemy 1.x）        # 新式（SQLAlchemy 2.0，项目使用）
id = Column(Integer, primary_key=True)    →    id: Mapped[int] = mapped_column(primary_key=True)
name = Column(String(64))                 →    name: Mapped[str] = mapped_column(String(64))
```

`Mapped[str | None]` 直接对应 Python 类型注解，比旧式更直观。

### 3.2 异步会话（AsyncSession）

`backend/packages/harness/deerflow/persistence/engine.py`：
```python
from sqlalchemy.ext.asyncio import async_sessionmaker, AsyncSession

_session_factory: async_sessionmaker[AsyncSession] | None = None
```

使用模式——短生命周期会话：
```python
async with self._sf() as session:     # 自动 open/close
    session.add(row)
    await session.commit()             # 显式提交
```

`async with` 确保会话在块结束时自动关闭，即使发生异常。

### 3.3 异步查询

`backend/packages/harness/deerflow/persistence/run/sql.py`：
```python
from sqlalchemy import select, func

# 简单查询
async with self._sf() as session:
    row = await session.get(RunRow, run_id)

# 条件查询
stmt = select(UserRow).where(UserRow.system_role == "admin").limit(1)
row = (await session.execute(stmt)).scalar_one_or_none()

# 聚合查询
model_name = func.coalesce(RunRow.model_name, "unknown")
stmt = (
    select(
        model_name.label("model"),
        func.count().label("runs"),
        func.sum(RunRow.total_tokens).label("total_tokens"),
    )
    .where(RunRow.thread_id == thread_id)
    .group_by(model_name)
)
rows = (await session.execute(stmt)).all()
```

## 4. uv 与现代 Python 打包

### 4.1 为什么用 uv

**其他语言类比**：uv ≈ Rust 的 cargo 或 Node.js 的 pnpm——极快的包管理器，替代 pip + virtualenv。

核心命令：
```bash
uv sync          # 安装所有依赖（类似 npm install）
uv run pytest    # 在虚拟环境中运行命令（类似 npx）
uv add package   # 添加依赖（类似 npm install package）
uv lock          # 锁定依赖版本（类似 npm shrinkwrap）
```

### 4.2 项目包结构

```
backend/
├── pyproject.toml              # 主项目配置
├── packages/
│   └── harness/
│       ├── pyproject.toml      # deerflow-harness 包配置
│       └── deerflow/           # 包源码
```

主项目 `backend/pyproject.toml`：
```toml
[project]
name = "deer-flow-backend"
dependencies = [
    "deerflow-harness",              # 引用子包
    "fastapi>=0.115.0",
    "uvicorn[standard]>=0.34.0",
]

[tool.uv.workspace]
members = ["packages/harness"]       # workspace 成员

[tool.uv.sources]
deerflow-harness = { workspace = true }  # 本地 workspace 引用
```

子包 `packages/harness/pyproject.toml`：
```toml
[project]
name = "deerflow-harness"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
    "langchain>=1.2.15",
    "langgraph>=1.1.9",
    "sqlalchemy[asyncio]>=2.0,<3.0",
]
```

**关键概念**：workspace 让 `deerflow-harness` 包在开发时以本地源码形式存在，发布时作为独立 PyPI 包。

### 4.3 常用开发命令

```bash
# 根目录
make install     # 前后端依赖全装
make dev         # 启动所有服务

# backend 目录
make dev         # 只跑 Gateway API（端口 8001）
```

## 5. Docker 与 Nginx — 部署基础设施

### 5.1 服务拓扑

```
                  Nginx (端口 2026，统一入口)
                  ┌──────────┐
用户浏览器 ──────→│  /api/*   │────→ Gateway API (FastAPI, 端口 8001)
                  │  /       │────→ Frontend (Next.js, 端口 3000)
                  └──────────┘
```

Nginx 的核心职责：
- **路由分发**：`/api/*` → 后端，`/*` → 前端
- **SSE 代理**：关闭缓冲，让流式事件实时到达
- **文件上传**：设置 `client_max_body_size`

### 5.2 Docker Compose

`docker/docker-compose.yaml`：
```yaml
services:
  nginx:
    image: nginx:alpine
    ports:
      - "${PORT:-2026}:2026"        # 对外暴露端口

  gateway:
    command: >
      uv run uvicorn app.gateway.app:app
      --host 0.0.0.0 --port 8001
      --workers ${GATEWAY_WORKERS:-4}
    volumes:
      - config.yaml:/app/backend/config.yaml:ro  # 配置文件挂载

  frontend:
    build:
      context: ../
      dockerfile: frontend/Dockerfile
```

### 5.3 Nginx 路由规则

`docker/nginx/nginx.conf` 关键片段：
```nginx
# LangGraph 兼容路由 → 后端
location /api/langgraph/ {
    rewrite ^/api/langgraph/(.*) /api/$1 break;
    proxy_pass http://gateway:8001;
    proxy_buffering off;              # SSE 关键！
}

# 文件上传 → 后端（放宽 body 大小限制）
location ~ ^/api/threads/[^/]+/uploads {
    proxy_pass http://gateway:8001;
    client_max_body_size 100M;
}

# 其他所有 / → 前端
location / {
    proxy_pass http://frontend:3000;
}
```

### 5.4 开发 vs 生产

| | 开发模式 (`make dev`) | 生产模式 (`make up`) |
|---|---|---|
| 前端 | `next dev` 热重载 | 预构建静态文件 |
| 后端 | `uvicorn --reload` | `uvicorn --workers 4` |
| Nginx | 本地进程 | Docker 容器 |
| 配置 | `config.yaml` 本地文件 | Docker volume 挂载 |

### 6.5 前后端数据流（完整链路）

```
用户输入 "帮我研究 AI"
  ↓
前端 useStream 发起 SSE 请求 → nginx → Gateway /api/threads/{id}/runs/stream
  ↓
Gateway 创建 RunRecord → 启动 Agent worker
  ↓
Agent.astream() → middleware chain → LLM → tools → ...
  ↓
worker 调用 StreamBridge.publish()
  ↓
StreamBridge → sse_consumer() → SSE 事件
  ↓
nginx（proxy_buffering off）→ 浏览器
  ↓
前端 useStream.onUpdateEvent() → React re-render
```

## 速查清单：6 个领域最容易困惑的点

| 看到这个 | 它是什么 | 关键理解 |
|---------|---------|---------|
| `Depends(get_config)` | FastAPI 依赖注入 | 框架自动调用函数，把结果传给参数 |
| `StreamingResponse(gen, media_type="text/event-stream")` | SSE 端点 | gen 是 async generator，每次 yield 一个 SSE 事件 |
| `X-Accel-Buffering: no` | nginx 不缓冲 | SSE 必须设置，否则事件被攒在一起 |
| `Mapped[str] = mapped_column(...)` | SQLAlchemy 2.0 模型字段 | 类型注解驱动，比旧式 Column() 更清晰 |
| `async with session` | 异步数据库会话 | 自动 open/commit/close |
| `uv sync` | 安装依赖 | 比 pip 快 10-100x，自动创建 venv |
| `[tool.uv.workspace]` | monorepo 包管理 | 类似 pnpm workspace |
| `proxy_buffering off` | nginx SSE 配置 | 不缓冲，让事件实时流过 |
| `useStream()` | 前端 SSE Hook | LangGraph SDK 封装，自动管理连接和重连 |
| `app.state.config` | FastAPI 共享状态 | lifespan 写入，路由中通过 `request.app.state` 读取 |
