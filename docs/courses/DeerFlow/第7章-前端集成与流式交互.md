## 7.2 通信架构：SSE + REST 双通道

前端通过两种方式与后端通信：

```
┌──────────────┐          ┌──────────────┐
│   前端 Next.js│          │  Nginx :2026  │
│   (port 3000) │          └───────┬──────┘
└──────┬───────┘                  │
       │                          │
       │  ┌───────────────────────┤
       │  │                       │
       ↓  ↓                       ↓
  ┌────────────┐          ┌──────────────┐
  │ LangGraph   │  SSE    │  FastAPI      │  REST
  │ Server      │←───────│  Gateway      │
  │ (port 2024) │        │  (port 8001)  │
  └────────────┘         └──────────────┘
```

### SSE（Server-Sent Events）—— 主要通道

用于实时流式通信：

- 创建线程、提交消息、接收 AI 回复
- 工具调用状态实时更新
- 子 Agent 执行进度

SSE 是 DeerFlow 前后端通信的核心通道。前端通过 `@langchain/langgraph-sdk` 的 `useStream` hook 建立连接，后端通过 `StreamBridge` 发布事件。具体的实体定义、数据结构和完整通信案例将在下一章详细展开。

### REST API —— 辅助通道

用于非实时操作：

| 功能 | 端点 | 方法 |
|------|------|------|
| 历史消息加载 | `/api/threads/{id}/runs/{rid}/messages` | GET |
| 模型列表 | `/api/models` | GET |
| 文件上传 | `/api/threads/{id}/uploads` | POST |
| Token 使用统计 | `/api/threads/{id}/token-usage` | GET |
| 记忆管理 | `/api/memory` | GET/POST |
| 技能管理 | `/api/skills` | GET/PUT |
| 建议生成 | `/api/threads/{id}/suggestions` | POST |

### 核心状态管理

前端使用三类状态源：

| 状态类型 | 管理方式 | 用途 |
|---------|---------|------|
| 服务端状态 | TanStack Query | 线程列表、模型列表、历史消息 |
| 流式状态 | `useStream` hook | 实时消息、工具状态、子 Agent 进度 |
| 本地状态 | React useState/useRef | 乐观消息、上传进度、UI 状态 |

三者通过 `mergeMessages()` 函数合并为最终显示的消息列表。

## 7.4 认证与安全

### CSRF 保护

使用 **Double Submit Cookie** 模式：

```typescript
// api-client.ts
onRequest: (request) => {
  // 对状态变更操作注入 CSRF Token
  if (["POST", "PUT", "PATCH", "DELETE"].includes(request.method)) {
    request.headers.set("X-CSRF-Token", getCSRFToken());
  }
  return request;
}
```

### 认证

```typescript
// HttpOnly Cookie + credentials: "include"
fetch(url, { credentials: "include" });

// 401 自动跳转登录
if (response.status === 401) {
  window.location.href = "/login";
}
```

## 思考题

**题 1**：DeerFlow 前端选择 SSE 而非 WebSocket 作为主要通信协议。在 Agent 流式场景下，SSE 和 WebSocket 各有什么优劣？

> **参考答案**：SSE 的优势：1）**简单性**——SSE 是单向的（服务端→客户端），正好匹配 AI 回复的流式场景；2）**自动重连**——浏览器原生支持；3）**HTTP 兼容**——走标准 HTTP，天然兼容代理、防火墙、CDN。WebSocket 的优势在于双向通信和低延迟，但 Agent 场景天然是「请求-流式响应」模式，不需要双向通信。下一章将深入分析 SSE 的具体实现。

**题 2**：前端使用三类状态源（服务端状态、流式状态、本地状态）来管理消息。这种设计有什么好处？如果只用一类状态源会有什么问题？

> **参考答案**：分离的好处是关注点分离——TanStack Query 管理持久化数据（缓存、刷新、分页），`useStream` 管理实时数据（增量更新、断线重连），本地状态管理临时 UI 状态（乐观消息、加载指示器）。如果只用一类：用服务端状态则无法处理实时流式更新；用流式状态则历史消息加载和缓存管理会很笨拙；用本地状态则无法持久化和自动刷新。
