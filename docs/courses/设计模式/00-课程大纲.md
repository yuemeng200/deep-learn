# Go 设计模式课程大纲

> 面向：前端转全栈 Go 开发者
> 定位：初级阶段
> 主线项目：「LinkFlow」短链与跳转分析服务

---

## 核心本质

设计模式解决的根本问题是：**如何在代码规模增长时，依然能低成本地修改和扩展系统**。每一个模式背后都是一个反复出现的痛点——"这段代码改不动了"、"加新功能要改十个地方"、"一换数据库全炸了"。

Go 对设计模式有自己的态度：**组合优于继承，接口即契约，显式优于魔法**。经典的 23 种 GoF 模式在 Go 中很多被简化甚至合并，也诞生了一些 Go 独有的惯用写法（如 Functional Options）。这门课不追求模式的完整性，只聚焦那些在 Go 生产 Web 应用中真正高频、真正有用的部分。

---

## 实战项目

**「LinkFlow」—— 一个生产级短链与跳转分析服务**

用户可以创建短链，访问短链时记录事件，后台支持多种存储后端、多种通知渠道、灵活的中间件链。

选它的原因：短链服务结构简单但扩展点丰富——存储可换（内存/Redis/MySQL）、通知可扩展（日志/Webhook/邮件）、行为可组合（鉴权/限流/日志中间件），天然适合逐章引入不同模式，最终形成一个完整的生产级架构。

---

## 课程大纲

**第1章：Go 中的设计模式思维**
Go 没有类和继承，模式在这里长什么样？建立"接口即契约、组合替代继承"的核心认知，搭建 LinkFlow 项目骨架，写出第一个可运行的 HTTP 服务。

**第2章：创建型模式——把"怎么造"和"怎么用"分开**
Singleton（全局唯一的 DB 连接、Config）、Factory（根据配置创建不同存储后端）、Functional Options（Go 最地道的对象构造方式）。产出：可通过配置切换存储层的服务初始化模块。

**第3章：结构型模式——Repository 与依赖注入**
Repository 模式（让业务层完全不知道数据库的存在）、手动依赖注入（不用框架，理解本质）。产出：短链的增删查改，业务逻辑与存储完全解耦，可无缝切换内存/MySQL 实现。

**第4章：行为型模式 I——策略模式与中间件链**
Strategy（不同的跳转统计策略：同步写库 vs 异步队列）、Chain of Responsibility（HTTP 中间件：日志 → 鉴权 → 限流，顺序可组合）。产出：一套可灵活配置的中间件系统 + 可插拔的统计策略。

**第5章：行为型模式 II——观察者与事件驱动**
Observer / Event Bus（短链被访问时，触发多个下游动作：记录日志、发 Webhook、更新缓存），理解事件驱动架构如何降低模块耦合。产出：内置事件总线，新增下游处理器无需修改核心流程。

**第6章：整合与生产实践**
将前五章的模块串联成完整服务，补入两个生产必备模式：Circuit Breaker（下游挂了不拖垮自己）和 Graceful Shutdown（优雅退出）。最终产出：一个结构清晰、可扩展、能上线的 LinkFlow 完整项目。
