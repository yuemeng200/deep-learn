# 第 6 章：跨端技术路线，React Native、Flutter 与原生混合接入

跨端技术的本质不是“少写一半代码”这么简单，而是在复用效率、原生能力、性能上限、团队技能和长期维护之间做工程权衡。

前面几章我们已经讨论了原生平台、UI 架构和数据层。这一章把 React Native、Flutter 和原生混合接入放到同一张图里，理解它们分别复用了什么，又在哪里必须回到原生。

## 1. 跨端方案到底想解决什么

跨端方案通常试图解决几类问题：

- iOS 和 Android 重复开发成本高。
- 业务页面迭代速度不够快。
- 前端团队希望参与 App 页面开发。
- 希望核心业务逻辑和 UI 在多端保持一致。
- 希望部分页面可以独立于原生主工程快速演进。

但跨端也会引入新的复杂度：

- 跨端运行时本身的学习成本。
- 原生能力桥接成本。
- 性能问题定位复杂。
- 三套生态版本兼容。
- 原生团队和跨端团队的协作边界。
- 打包、发布、灰度、监控链路更复杂。

所以跨端不是“比原生先进”，也不是“性能一定差”。它是一种组织代码和团队能力的路线。

## 2. React Native：用 React 心智协调 JS 与原生

React Native 的核心思路是：用 JavaScript/TypeScript 和 React 组织业务逻辑与 UI 描述，再映射到原生平台能力。

可以简化理解为：

```text
React Component / JS business logic
  -> React Native runtime
  -> Native UI / Native Module
  -> iOS / Android platform
```

RN 的优势：

- 对 React 前端开发者迁移友好。
- 可以复用一部分前端状态管理、工程和组件思想。
- 能访问原生能力，适合混合接入。
- 业务页面迭代效率通常较高。

RN 的关键边界：

- JS runtime 和 Native runtime 之间的通信。
- 原生模块的封装和维护。
- 列表、动画、手势、复杂交互的性能。
- 新架构迁移和第三方库兼容。
- iOS/Android 行为差异仍然存在。

RN 不等于 WebView。它不是把网页塞进 App，而是用 React 描述界面，再让原生平台渲染或承载对应 UI。

## 3. Flutter：自带渲染体系的跨端 UI runtime

Flutter 的核心思路是：用 Dart 和 Widget Tree 描述界面，通过自己的框架和渲染引擎绘制 UI。

可以简化理解为：

```text
Dart / Widget Tree
  -> Flutter Framework
  -> Flutter Engine
  -> Skia / Impeller rendering
  -> iOS / Android surface
```

Flutter 的优势：

- UI 一致性强。
- 渲染模型统一，可控性高。
- 适合高度定制 UI 和跨端一致体验。
- 框架、工具链和组件体系相对完整。

Flutter 的关键边界：

- 团队需要接受 Dart 和 Flutter 生态。
- 与原生平台能力通过插件和 Platform Channels 连接。
- 原生页面混合接入需要处理容器、路由、生命周期。
- 包体、首屏、引擎初始化和平台视图混合需要关注。
- 原生系统控件的一致性需要自己权衡。

Flutter 更像一套独立客户端技术栈，而不是前端技术在移动端的延伸。

## 4. RN 与 Flutter 的核心差异

| 维度 | React Native | Flutter |
| --- | --- | --- |
| 主要语言 | JavaScript / TypeScript | Dart |
| UI 心智 | React 组件模型 | Widget Tree |
| 渲染路线 | 协调 JS 与原生 UI/平台能力 | 自带渲染引擎绘制 UI |
| 前端迁移成本 | 对 React 开发者较低 | 需要学习 Dart 和 Flutter 体系 |
| 跨端一致性 | 依赖组件、平台差异和原生表现 | 一致性通常更强 |
| 原生能力 | Native Module / Turbo Module | Plugin / Platform Channels |
| 性能关注点 | JS/Native 边界、列表、动画、桥接 | 渲染、引擎、平台视图、包体 |
| 混合接入 | 常见于已有原生 App 的业务页面 | 可行，但容器和引擎管理更关键 |

选择时不要问“哪个更好”，而要问：

- 团队已有技能是什么？
- 业务页面需要多强的原生一致性？
- UI 是否高度定制？
- 是否大量依赖原生 SDK？
- 性能风险集中在哪里？
- 现有 App 是原生为主，还是跨端为主？
- 长期维护由谁负责？

## 5. 原生混合接入：真实公司里最常见的形态

很多业务不是纯原生，也不是纯跨端，而是混合：

```text
原生 App Shell
  Tab / 登录 / 支付 / 推送 / 原生 SDK / 基础能力

业务页面
  原生页面
  React Native 页面
  Flutter 页面
  WebView 页面

基础服务
  路由、埋点、网络、鉴权、配置、灰度、监控
```

混合架构里最重要的是边界治理：

- 路由如何统一？
- 登录态如何共享？
- 网络层是否统一？
- 埋点字段是否一致？
- 错误日志如何归因？
- 跨端页面如何调用原生能力？
- 原生页面如何打开跨端页面？
- 版本兼容如何处理？

如果没有这些基础设施，跨端页面会变成孤岛。

## 6. 哪些页面适合跨端，哪些更适合原生

适合跨端的场景：

- 中低复杂度业务页面。
- 表单、列表、详情、设置类页面。
- 需要 iOS/Android 快速保持一致的页面。
- 迭代频繁、平台能力依赖较少的页面。
- 前端团队主导的业务模块。

更适合原生的场景：

- 强依赖系统能力：相机深度定制、蓝牙、音视频、后台定位。
- 强性能场景：复杂动画、高频渲染、大型列表、实时互动。
- 平台规范要求高：支付、登录、安全、通知核心链路。
- 与原生 SDK 深度耦合的模块。
- App 启动、基础导航、核心容器、基础服务。

也有中间地带。比如头像上传页面可以用 RN/Flutter 写 UI，但图片选择、裁剪、权限和上传底层能力可能由原生模块或插件提供。

## 7. 跨端性能问题通常发生在哪里

RN 常见性能关注点：

- JS 线程忙导致交互卡顿。
- 大列表渲染和重排。
- JS 与 Native 频繁通信。
- 动画和手势处理不当。
- 图片过大、内存占用高。
- 第三方原生模块质量不稳定。

Flutter 常见性能关注点：

- Widget rebuild 范围过大。
- 列表和图片资源管理不当。
- 平台视图混合带来的开销。
- 引擎初始化和首屏耗时。
- 动画和自定义绘制过重。
- 包体和资源体积控制不足。

跨端性能优化的共同原则是：先定位瓶颈属于 UI 渲染、业务计算、桥接通信、图片资源、网络数据，还是原生平台能力。不要只凭技术栈刻板印象下结论。

  是否需要高性能动画：
  是否需要快速多端一致：

  路由由谁打开：

## 9. 轻量验证：订单详情页选型推演

| 条件 | 更偏向 |
| --- | --- |
| 普通详情展示、列表、按钮、状态流转 | RN 或 Flutter |
| 团队大量 React 经验，已有 RN 基础设施 | RN |
| 需要高度一致的定制 UI，团队接受 Dart | Flutter |
| 深度依赖支付、安全、复杂原生 SDK | 原生或原生主导 |
| 只是临时活动页，分发要求极快 | WebView 或已有动态化体系 |
| App Shell、启动、基础路由、推送 | 原生 |

选型不是一次性答案。真实公司里更重要的是已有技术栈和基础设施。如果团队已经有成熟 RN 体系，继续用 RN 的收益可能大于引入 Flutter；反过来也一样。

## 10. 本章小结

- 跨端技术解决的是复用效率和多端一致性问题，但会引入运行时、桥接、性能和协作复杂度。
- React Native 更适合有 React 经验的团队，用 JS/React 心智协调原生 UI 和能力。
- Flutter 更像独立客户端技术栈，通过自带渲染体系获得更强 UI 一致性。
- 真实 App 常见形态是原生 Shell + 跨端业务页面 + 统一基础服务。
- 跨端选型要看业务特征、平台能力、性能风险、团队技能和已有基础设施。
- AI Coding 参与跨端开发时，必须给出平台边界和基础设施上下文。

第 7 章会进入工程化、质量与性能：为什么客户端业务迭代不能只看功能跑通。

## 思考题

### 题 1：为什么跨端不等于“一套代码解决所有问题”？

参考答案：

因为跨端主要复用 UI 和部分业务逻辑，但相机、定位、支付、通知、后台任务、发布、崩溃和性能仍然受 iOS/Android 平台影响。跨端还需要处理桥接、插件、路由、登录态、埋点、监控和版本兼容。

### 题 2：RN 和 Flutter 的根本差异是什么？

参考答案：

RN 用 React/JS 心智组织业务和 UI，再协调原生平台能力；关键边界是 JS 与 Native。Flutter 用 Dart 和 Widget Tree 构建自己的 UI runtime，通过引擎绘制界面；关键边界是 Flutter runtime 与原生平台能力。前者更贴近 React 生态，后者更强调自有渲染和跨端一致性。

### 题 3：哪些因素比“技术先进”更影响跨端选型？

参考答案：

团队已有技能、现有基础设施、业务页面复杂度、原生能力依赖、性能要求、长期维护责任、发布链路、监控体系和历史包袱，通常比技术本身是否流行更重要。
