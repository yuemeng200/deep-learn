# 现代客户端开发架构与 AI 辅助实践 渐进式学习课程

## 学员定位

你已经具备前端和后端开发经验，也曾使用 SwiftUI、React Native 等技术栈做过 App，但过去更多依赖 AI Coding 完成功能，因此对客户端技术栈的整体设计、平台差异、跨端路线、架构演进和工程判断还缺少系统认知。

你未来更可能参与的是已有 App 中的业务功能迭代，而不是从 0 到 1 搭建完整客户端工程。因此本课程不会从语言语法或单个 API 开始，而是帮助你建立一套能用于阅读现有代码、理解架构边界、和客户端同事高质量沟通、并在 AI 辅助下独立开发的宏观框架。

认知阶段：初级到中级过渡。

课程模式：混合型，主线是问题链 + 轻量验证。每章先建立架构心智模型，再通过对照表、概念图、代码阅读检查点或小型推演验证关键判断。

## 核心本质

客户端开发解决的根本问题，不只是“把界面画出来”，而是在用户设备这个受限、异构、强交互的运行环境中，把业务状态、平台能力、网络数据、界面渲染、生命周期、性能和稳定性组织成一个可持续演进的产品体验。

Web 前端通常运行在浏览器抽象之上，很多平台差异被浏览器、HTTP、DOM、CSS、JS runtime 和前端框架屏蔽。但移动客户端直接面对的是操作系统、设备硬件、应用生命周期、权限模型、线程模型、包体限制、离线与弱网、崩溃恢复、应用商店发布、原生 SDK 和系统能力。它的复杂度不一定来自语法，而是来自运行环境更贴近设备、更贴近系统、更贴近真实用户使用场景。

现代客户端架构的设计哲学可以概括为：

1. 把界面从一次性渲染，理解为状态、事件和系统生命周期共同驱动的持续过程。
2. 把业务功能从页面代码中抽离出来，分层组织为 UI、状态、领域逻辑、数据访问和平台能力。
3. 把 iOS、Android、React Native、Flutter 看成不同的运行时、渲染模型与工程边界，而不是几套完全无关的技能。
4. 把跨端方案理解为“复用哪些东西、牺牲哪些东西、在哪里回到原生”的权衡，而不是简单的“一套代码跑两端”。
5. 把 AI Coding 当作加速器，而不是替代架构判断、平台约束判断和质量判断的黑盒。

所以，这门课的目标不是让你背 SwiftUI、UIKit、Kotlin、Jetpack Compose、React Native 或 Flutter 的 API，而是让你能判断：一个业务需求在客户端里会穿过哪些层，应该放在哪个边界上实现，什么时候用原生，什么时候用跨端，什么时候要关注生命周期、线程、缓存、权限、性能、稳定性和发布风险。

## 课程主线

课程用一条问题链推进：

> 一个有前端/全栈背景的开发者，如何在 AI Coding 辅助下，快速进入现代客户端团队，并能独立完成业务迭代、理解现有架构、判断技术方案是否合理？

主线会同时覆盖：

- iOS 侧：Swift/SwiftUI/UIKit 生态位置、应用生命周期、View 与状态模型、原生能力、包管理和工程结构。
- Android 侧：Kotlin/Java 生态位置、Activity/Fragment/Compose、Jetpack、Gradle、生命周期、权限和系统能力。
- React Native 侧：JS/Native 双运行时、Bridge/JSI/New Architecture、原生模块、页面集成、跨端复用与性能边界。
- Flutter 侧：Dart、Widget Tree、Skia/Impeller 渲染管线、Engine/Framework 分层、Platform Channels、插件生态和混合接入。
- 通用客户端架构：UI 分层、状态管理、数据流、网络、缓存、离线、错误处理、模块化、依赖注入、测试、可观测性。
- 业务迭代方法：如何读一个现有 App、如何定位功能入口、如何修改一条业务链路、如何验证影响面。
- AI Coding 协作：如何给 AI 提供上下文，如何审查生成代码，如何识别平台层面的错误假设，如何把 AI 变成客户端开发中的可靠工具。

## 课程大纲

### 第 1 章：客户端开发的全局地图，和 Web 前端到底哪里不同

核心问题：为什么会写 React 或后端，并不等于天然理解客户端？

本章会建立客户端的整体地图：App 运行在操作系统之上，面对设备、生命周期、权限、网络、存储、线程、发布和崩溃等约束。你会把 Web、iOS、Android、React Native、Flutter 放到同一张技术地图里，理解它们分别抽象了什么，又暴露了什么。

产出：客户端技术地图 + Web 前端到客户端的认知迁移表。

### 第 2 章：iOS 与 Android 的平台模型，先理解操作系统再理解框架

核心问题：iOS 和 Android 的差异，究竟是语言差异、框架差异，还是系统模型差异？

本章会从应用生命周期、页面/导航模型、权限、安全沙箱、后台任务、通知、文件存储、系统服务、包管理和发布流程切入，建立 iOS 与 Android 的平台心智模型。SwiftUI、UIKit、Kotlin、Jetpack Compose、Activity、Fragment 会被放在平台演进脉络中理解，而不是作为孤立 API 学习。

产出：iOS/Android 平台模型对照表 + 常见业务需求的平台影响面清单。

### 第 3 章：客户端 UI 架构，声明式 UI、状态驱动和页面生命周期

核心问题：现代客户端 UI 为什么越来越像 React，但又不能简单套用 Web 心智？

本章会对比 React、SwiftUI、Jetpack Compose、React Native 和 Flutter 的声明式 UI 思想，解释 View、State、Props/Binding、Observable、ViewModel、Effect、Navigation、生命周期回调之间的关系。重点不是语法，而是理解“状态改变驱动界面”和“系统生命周期打断界面”的双重模型。

产出：声明式 UI 心智模型图 + 一个业务页面的状态拆分练习。

### 第 4 章：业务功能如何穿过客户端分层

核心问题：一个按钮点击到服务端数据变化，中间到底经过了哪些层？

本章会以“修改用户资料”“提交订单”“进入详情页”这类业务迭代为例，拆解 UI 层、状态层、领域逻辑、网络层、缓存层、本地存储、错误处理、埋点和权限检查如何协作。你会理解 MVC、MVVM、MVI、Clean Architecture、Repository、Use Case 等名词背后的真实意图。

产出：业务链路分层图 + 现有 App 功能阅读 checklist。

### 第 5 章：数据、网络、缓存与离线，客户端不是薄薄一层 UI

核心问题：为什么客户端经常要处理缓存、一致性、弱网和本地状态，而不能只等后端返回？

本章会系统理解 API 请求、鉴权、错误码、重试、分页、预加载、本地数据库、Key-Value 存储、图片缓存、离线草稿、乐观更新和数据一致性。重点是从用户体验和设备环境出发判断数据策略，而不是学习某个网络库的调用方式。

产出：客户端数据状态分类表 + 弱网/离线场景设计推演。

### 第 6 章：跨端技术路线，React Native、Flutter 与原生混合接入

核心问题：跨端技术的本质是复用业务代码，还是重新定义客户端运行时？

本章会把 React Native 和 Flutter 放在同一张跨端路线图里对比：RN 侧重用 React 心智协调 JS 与原生 UI，Flutter 则通过自带渲染引擎和 Widget 体系提供更完整的一致性抽象。你会理解 RN 的双运行时、JS 线程、Bridge/JSI、新架构、原生模块，也会理解 Flutter 的 Dart、Widget Tree、Engine/Framework 分层、Skia/Impeller、Platform Channels 和插件机制。重点是判断哪些业务页面适合跨端，哪些能力必须回到原生，性能问题通常发生在哪些边界，以及跨端团队如何和原生团队协作。

产出：React Native / Flutter 架构对照图 + 跨端/原生选型决策表。

### 第 7 章：客户端工程化、质量与性能，业务迭代为什么不能只看功能跑通

核心问题：客户端代码上线后，为什么崩溃、卡顿、包体、启动、耗电和兼容性会成为架构问题？

本章会覆盖模块化、依赖管理、构建系统、环境配置、CI/CD、测试金字塔、崩溃监控、日志、埋点、性能指标、启动优化、列表性能、内存泄漏、包体控制和灰度发布。你会建立“客户端质量不是测试阶段补救，而是架构阶段持续约束”的认知。

产出：客户端质量指标地图 + 业务需求上线前风险检查表。

### 第 8 章：AI Coding 时代的客户端开发方法

核心问题：如果大部分代码由 AI 帮你写，你作为开发者真正需要掌握什么？

本章会把前面所有概念收束到实际工作方法：如何让 AI 读懂现有 App 架构，如何拆解一个客户端需求，如何限定 iOS/Android/RN/Flutter 的实现边界，如何审查 AI 生成的生命周期、线程、权限、状态管理和错误处理代码，如何设计最小验证路径，以及如何和原生客户端同事沟通方案。

产出：AI 辅助客户端开发工作流 + Prompt 上下文模板 + 代码审查 checklist。

## 课程完成后的能力目标

完成课程后，你应该能够：

1. 从宏观上解释 iOS、Android、React Native、Flutter 在现代客户端体系中的位置和边界。
2. 看懂一个已有客户端业务功能大致穿过哪些架构层，并能判断改动影响面。
3. 理解声明式 UI、状态管理、生命周期、导航和平台能力之间的关系。
4. 判断一个业务需求更适合原生实现、React Native 实现、Flutter 实现，还是混合实现。
5. 对客户端数据、缓存、离线、弱网、错误处理、性能和稳定性建立基本工程判断。
6. 在 AI Coding 辅助下提出更准确的上下文、审查更关键的问题，而不是只看生成代码是否能编译。
7. 和 iOS、Android、React Native、Flutter 开发者围绕架构、质量和交付风险进行高质量沟通。

## 参考基线

本课程不以具体 API 速查为目标，而以 2026 年主流客户端开发范式为基线：

- iOS：Swift、SwiftUI、UIKit、Combine/Observation、Swift Package Manager、Xcode 工程体系。
- Android：Kotlin、Jetpack、Jetpack Compose、Activity/Fragment、ViewModel、Flow、Gradle 工程体系。
- React Native：React、TypeScript、Metro、Native Modules、JSI、Fabric、Turbo Modules、新架构和原生混合接入。
- Flutter：Dart、Widget、Element/RenderObject、Engine、Skia/Impeller、Platform Channels、插件生态和原生混合接入。
- 通用工程：MVVM/MVI/Clean Architecture、Repository、依赖注入、测试、监控、性能优化、发布和灰度。
