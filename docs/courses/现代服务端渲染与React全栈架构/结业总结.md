# 现代服务端渲染与 React 全栈架构 结业总结

## 核心理念提炼

这门课的核心不是“学会 Next.js”或“学会 SSR”，而是建立现代 React 全栈架构的边界判断力。

CSR 的默认世界观是：浏览器拿到应用壳，下载 JS，客户端路由匹配，组件挂载后请求数据，再渲染 UI。这个模型在高交互应用中仍然有效，但它把太多工作默认推给了浏览器。

现代 SSR/RSC 体系的本质，是重新分配这些工作：

```txt
构建期:
  提前生成稳定公开内容

服务端:
  获取路由主数据、生成 HTML、运行 Server Components

Streaming:
  让慢区域不阻塞快区域

客户端:
  承担交互、本地状态、浏览器 API 和活跃 server state

缓存层:
  复用数据、组件、路由结果和 HTTP 响应

运行时:
  在 Node、Edge、浏览器之间选择合适执行位置
```

你需要掌握的最终问题不是：

```txt
这个页面要不要 SSR？
```

而是：

```txt
这部分 UI 的 HTML、数据、组件代码、缓存、交互和 mutation，分别应该在哪里发生？
```

课程的关键结论：

1. SSR 解决初始 HTML 可见，不直接等于交互可用。
2. Hydration 是浏览器把服务端 HTML 接管成 React 应用的过程。
3. Streaming SSR 用 Suspense 边界改变阻塞关系。
4. RSC 不是 SSR 的同义词，而是组件是否进入客户端 bundle 的边界。
5. Client Component 不等于纯 CSR；它通常可以有服务端 HTML preview，但需要 hydration。
6. Next App Router 是 RSC-first 的完整应用框架。
7. React Router Framework Mode 是 loader/action-first 的 Web 数据路由框架。
8. TanStack Query 仍然适合客户端长期活跃的 server state。
9. 缓存必须分层理解：Query cache、framework cache、HTTP cache、CDN cache 不是一回事。
10. Node runtime 和 Edge runtime 是能力模型差异，不是简单性能等级差异。

## 学员评估与定位

你的起点是资深 CSR 前端，已经理解 Node.js、HTTP、CDN、流式响应、边缘运行时等概念，但缺少现代 SSR/RSC 的系统工程框架。

经过这门课，你的定位应该从：

```txt
我知道 SSR 大概是服务端渲染页面
```

升级为：

```txt
我能按页面区域拆分渲染、数据、缓存、交互和运行时边界，
并解释 Next App Router、React Router、TanStack Query 分别适合解决哪一类问题。
```

你现在应该具备的能力：

1. 区分 CSR、SSR、SSG、ISR/Revalidation、Streaming SSR、RSC、纯 CSR island。
2. 判断一个组件应该是 Server Component、Client Component，还是跳过 SSR 的纯 CSR 组件。
3. 解释 Next App Router 中 route segment、layout、page、loading、error、Server Action、Route Handler 的架构位置。
4. 解释 React Router loader/action/Form/revalidation 的数据流。
5. 判断 TanStack Query 与框架数据层的边界。
6. 为一个中等复杂页面画出渲染、数据、缓存、交互和运行时地图。
7. 在技术选型时说明为什么选择 Next、React Router、Query 或混合方案。

## 进阶方向

后续建议沿三个方向继续深入。

### 方向一：Next App Router 工程实战

目标：真正写一个 App Router 项目，把 RSC、Client Components、Server Actions、cache、revalidation、streaming 全部跑通。

建议练习：

1. 做一个文章 + 课程 + dashboard 小应用。
2. 文章详情用 Server Component 和 metadata。
3. 收藏按钮用 Client Component + Server Action。
4. 推荐列表用 Suspense/streaming。
5. 商品或课程实体用 tag revalidation。
6. 用 bundle analyzer 检查 `use client` 边界。
7. 检查 HTML、RSC payload、hydration 行为和缓存 header。

### 方向二：React Router Framework Mode 实战

目标：用 loader/action/Form 建立不同于 RSC-first 的 Web 数据路由心智。

建议练习：

1. 做一个项目管理 CRUD。
2. 列表页用 loader。
3. 新建、编辑、删除用 action。
4. 用 Form 和 fetcher 做局部提交。
5. 用 pending state 做提交态。
6. 观察 action 后 loader revalidation 的行为。
7. 对照 Next Server Actions 写一份架构比较。

### 方向三：缓存与运行时专项

目标：从“能写 SSR”升级到“能上线可靠 SSR”。

建议练习：

1. 给公开文章页配置 HTTP/CDN 缓存。
2. 给用户 dashboard 配置 private/no-store。
3. 对同一实体设计 path revalidation 和 tag revalidation。
4. 对比 Query staleTime 与 HTTP max-age。
5. 模拟 CDN stale-while-revalidate。
6. 对比 Node runtime 和 Edge runtime 可用 API。
7. 分析 serverless 冷启动和数据库连接池。

## 最后一句

现代 SSR/RSC 的成熟度，不体现在“是否用了最新框架”，而体现在你能不能把每一块 UI 放到正确的边界上。

当你能清楚解释：

```txt
这块为什么服务端渲染，
这块为什么是 Client Component，
这份数据为什么用 Query，
这个 mutation 为什么用 action，
这个缓存为什么按 tag 失效，
这段逻辑为什么不能放 Edge，
```

你就已经具备现代 React 全栈架构的核心判断力。
