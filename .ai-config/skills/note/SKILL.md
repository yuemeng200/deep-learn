# Note

把多轮对话浓缩为少量、可复用、可脱离上下文阅读的 Q&A 知识卡片，并按日保存到 `docs/notes/`。

## 步骤

1. 通读对话，忽略被推翻的方案、重复澄清、客套话、未采纳的试错过程。
2. 识别追问类型：
   - 主线深挖：并入同一条 Q&A，把递进洞察吸收到答案中。
   - Tangent：不独立成条，作为触发它的 Q&A 末尾 Tips。
   - 独立新问题：单独成条。
3. 写问题：问题本身必须能作为索引，读者看到问题就知道答案范围。
4. 写答案：结论前置，不写对话过程；保留必要前提；答案脱离原对话也能读懂。
5. 如果用户没有明确要求直接保存，先展示 Q&A 并等待确认。这是一个 `hard stop`：确认前不写入文件。
6. 写入 `docs/notes/`：
   - 文件路径：`docs/notes/YYYY-MM-DD.md`，文件名只能是日期。
   - 标签：从内容提炼 3-8 个英文小写关键词。
   - 文件不存在：创建新文件，一级标题为 `# YYYY-MM-DD · tag1, tag2, tag3`。
   - 文件已存在：读取最大 Q 编号，从 `Q{N+1}` 追加；不修改已有标题和内容。
   - 每个问题使用二级标题：`## Qn：问题`。
   - 更新 `docs/notes/index.md`，若当天链接不存在则追加 `- [YYYY-MM-DD](/notes/YYYY-MM-DD) · tag1, tag2`。
7. 回复写入文件路径和位置，不重复 Q&A 正文。

## 输出格式

```markdown
## Q1：[问题]

[答案]

> Tips：[旁支追问的结论，一两句话。仅当该 Q&A 有 Tangent 时加入。]
```

## Tangent 判断信号

- 追问由答案中的术语或名词触发。
- 追问答案很短。
- 追问后对话回到主线。
- 删除这条追问不影响主线 Q&A 完整性。
